# 缺陷登记

Sprint 2 回顾行动项 A6：自 Sprint 3 起登记缺陷，供回顾计算缺陷逃逸率。

## 规则

- 来源分三类：**开发自检**（编码时发现）、**测试**（单测/契约测试发现）、**验收 Demo**（演示或人工验收发现）。
- 缺陷逃逸率 = 验收 Demo 发现的缺陷数 ÷ 本 Sprint 总缺陷数。
- 编译失败、类型检查超时等构建期问题不登记为本表缺陷，记入回顾的工程问题。

## 表字段说明

本表按 IEEE 829 缺陷报告最小集改造（原表仅「编号|日期|Sprint|来源|描述|状态」，缺严重级、优先级、复现步骤、预期/实际、核销记录）。

| 字段 | 含义 |
|---|---|
| 编号 | 缺陷唯一标识（D-001 起顺序编号，不回收） |
| 标题 | 一句话现象摘要 |
| 严重级 | 高 / 中 / 低 —— 对用户可见性与数据正确性的影响面 |
| 优先级 | 高 / 中 / 低 —— 修复次序（与严重级相互独立） |
| 状态 | 已核销 / 顺延（**顺延必须写目标版本，不得静默搁置**） |
| 来源版本 | `Sprint N（YYYY-MM-DD · 来源类别）`；来源类别取「开发自检 / 测试 / 验收 Demo」之一，缺陷逃逸率按此列统计 |
| 复现步骤 | 触发缺陷的操作序列；原始描述未记载的写「见原描述」 |
| 预期 / 实际 | 预期 = 契约要求（判据出处见括注）；实际 = 实际观测 |
| 核销记录 | 修复版本 + 核销测试名（真实用例名）；未覆盖者如实写明；顺延项写目标版本与处置方式 |
