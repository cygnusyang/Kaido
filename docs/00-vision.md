# Kairo 愿景与项目章程

> 版本 0.1 · 2026-10-17 · 状态：草案
> 上游依据：OmniPlan 逆向分析（[FEATURE-BREAKDOWN.md](FEATURE-BREAKDOWN.md)）、OPC 工作台立项

## 1. 一句话定位

Kairo 是一个**辅助 AI 编码智能体（Claude Code、Codex 等）开发复杂项目的配套项目管理软件**——AI 时代的任务与排期管理。

## 2. 项目背景

1. **AI 编码智能体缺少调度侧的「对照物」。** Claude Code、Codex 等工具擅长执行，但复杂项目开发需要 WBS 分解、排期、状态追踪与进度对照；这些能力目前散落在对话上下文和临时 Markdown 里，没有独立软件承载。
2. **已有参考实现。** OmniPlan（macOS）验证了专业级项目管理软件的完整功能面：大纲、甘特、资源、调度引擎、违例检查、报告（本仓库已将其内置手册拆解为 175 条功能规格）。
3. **AI 时代的接口形态不同。** 传统项目管理软件面向「人点界面」；Kairo 的第一公民是**程序化接口**——AI 通过 MCP 或 CLI 读写任务与排期，人通过图形界面审阅与决策。
4. **Kairo 已有基础。** 前期已完成：OmniPlan 搜索机制 REA 逆向分析、SwiftUI MVP（任务 CRUD + AI 筛选 + 查找，17 项测试通过）、175 条功能规格与术语表。

## 3. 产品目的与核心工作流

核心闭环（AI 开发复杂项目的标准节奏）：

```
需求文档 ──AI 读取──▶ WBS 分解 ──▶ Kairo 排期管理 ──▶ AI 逐功能开发
     ▲                                                        │
     └──────────── AI 每完成一个功能，回写状态 ◀───────────────┘
```

- AI 在读取需求后，将项目拆解为 WBS（工作分解结构），录入 Kairo；
- Kairo 负责**排期**：依赖关系、时间线、里程碑、进度对照；
- AI 每开发完一个功能，**通过 MCP 或 CLI 更新该任务状态**，再开发下一个；
- 人随时在 macOS 应用中查看全局进度、审阅与干预。

## 4. 产品形态：跨平台核心 + 等价接口层

架构上分为**核心模块**与**若干等价的对外接口层**，接口层相互独立、能力对等：

| 接口层 | 服务对象 | 定位 |
|---|---|---|
| macOS 桌面应用 | 人 | 主力交互界面，原生体验 |
| MCP 服务 | AI 智能体（Claude Code 等） | 程序化读写的一等公民 |
| CLI | AI 智能体 / 脚本 / 终端用户 | 与 MCP 能力对等的命令行 |
| Claude Code 插件 | Claude Code 协作场景 | 开发时集成（斜杠命令、hooks） |

后续可扩展：Windows/Linux 前端、iOS/Android 移动端（读取、控制、修改）。

## 5. 平台策略

1. **macOS 是主力阵营**：大部分 AI 生态在 macOS 上，第一交付目标为 macOS。
2. **核心必须跨平台**：核心模块（数据模型、调度引擎、存储）不依赖 AppKit/SwiftUI，必须可在 Windows 与 Linux 运行。
3. **早期只做 macOS**：macOS 应用（及 MCP/CLI/插件）就绪后，才考虑其他平台。
4. 移动端属于后期：可以读取与控制，不承载编辑主力场景。

## 6. 范围边界（本期章程）

- **做**：跨平台核心 + macOS 应用 + MCP 服务 + CLI + Claude Code 插件；WBS/依赖/排期/状态回写闭环。
- **不做**（本期）：多用户协作服务器、移动端、Windows/Linux 前端、MS Project 互转。
- **继承**：`docs/features/` 的 175 条 OmniPlan 功能规格作为需求输入，按 AI 辅助场景重新定优先级。

## 7. 成功判据（G3 发布门槛，初稿）

1. Claude Code 通过 MCP 完成「读取需求 → 建 WBS → 排期 → 逐任务开发 → 回写状态」全闭环，全程无需人工点界面；
2. CLI 与 MCP 能力对等（同一操作清单均有暴露）；
3. macOS 应用可完整查看与编辑上述项目数据；
4. 核心模块在 Linux 上编译并通过同一套核心测试。
