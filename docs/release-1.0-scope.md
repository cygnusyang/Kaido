# Kairo 1.0 范围：功能清单与非目标

> 状态：定稿草案（2026-10-26）· 当前可安装版本 v0.17.3 · 本文是 1.0 的准入契约，变更需显式修订。

## 1. 定位

面向 **AI 编码智能体 + 人类评审** 的项目管理工具：AI 通过 MCP / CLI 读写 WBS、依赖与排期，人在 macOS 应用里审阅甘特、基线偏差与实际进度。1.0 = 「单机、单人、可交付」的完整闭环，不含协作与云端。

## 3. 1.0 准入判据（全部满足才发）

1. 全量测试绿：≥1342 例、0 失败，连续两次运行一致（排除并行噪声）。
2. 性能：5,000 任务 × 3 基线 decode ≤1 s（实测 0.155 s）；1,000 行翻窗 ≤16.7 ms（实测 4.9 ms）；其余渲染指标 ≤100 ms。
3. 缺陷表无「待修复」项；顺延项必须写明目标版本。
4. `.kairo` formatVersion 2 往返、v1 迁移、未来版本拒读三条用例常绿。
5. 文档齐备：README（双语）、QUICKSTART、ARCHITECTURE、`docs/release.md`、CHANGELOG 完整。
6. 撤回路径：任一版本可回滚到上一 tag（产物在 Release 中保留）。
7. **签名决策已定**：配证书（全链路签名+公证）或显式接受「未签名发布」并在 Release 说明与 `SIGNING.txt` 标注。

## 4. 非目标（1.0 明确不做）

| 项 | 原因 | 可能版本 |
| --- | --- | --- |
| 工作日历（周模板 / 节假日，F-22-06） | 现在按日历天排期；引入工作日制会改所有工期语义与既有基线可比性，需独立版本 | 1.x |
| 挣值指标（SV / SPI / CV / CPI） | 依赖成本与实际工时口径，单人工具收益低 | 1.x+ |
| 甘特「仅基线」「分割日程」 | 已有行内分轨满足对照需求；分割视图需重做行高契约 | 1.x |
| 多级表头分组 / 冻结列 | 与当前列模型（单一顺序 + 显隐）冲突，需重设列契约 | 2.0 |
| 基线 A vs B 直接对比 | 数值可导出后在表格里看；界面双基线对照需新视图 | 1.x |
| 崩溃自动恢复 / 版本历史 | 稳定化审计确认当前无自动保存；新增恢复草稿涉及写入路径与隐私，非 1.0 必需 | 1.x |
| 协作 / 云同步 / 多人权限 | 产品定位是单机单人；多用户需要身份、冲突合并、服务端 | 2.0 |
| Windows / Linux GUI | 架构为 macOS 原生（AppKit + SwiftUI）；Linux 仅核心/CLI/MCP 可编译 | 不在路线图 |
| 移动端 | 同上 | 不在路线图 |

## 5. 已知限制（1.0 接受，写进 Release 说明）

- **未签名发布**（若未配证书）：首启需右键打开，OTA 不覆盖签名校验失败场景。
- 甘特同时最多显示 **3 条**基线，第 4 条起只提示「另有 N 条未显示」。
- 绕过 `saveProject` 的自定义导出路径不补基线颜色（读取侧派生兜底）。
- 大纲行内取消与检查器取消**都需填原因**；不支持「无理由取消」。
- 无自动保存：崩溃会丢未保存修改（审计记录见 `docs/stability-audit-0.17.md`）。

## 6. 格式冻结承诺

从 1.0 起，`.kairo` **formatVersion 2** 的结构与语义冻结：

- 新增字段一律**加法 + 可选**，旧文件缺字段按默认值读取；
- 不重命名、不复用已废弃键；
- 破坏性变更必须升 `formatVersion` 并在 `FormatMigrationPlan` 提供相邻版本迁移，且至少保留一个大版本的可读性；
- 未来版本文件被旧客户端打开时必须**明确拒绝**（`unsupportedFormatVersion`），不允许静默降级或丢字段。
