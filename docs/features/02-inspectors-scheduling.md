# 二、检查器与调度引擎功能拆解（OmniPlan 手册 ch.20–30）

> 来源：OmniPlan 4 macOS 版内置简体中文参考手册（`OmniPlan Help/zh-Hans.lproj`），章节 2000–3000。
> 本文件为 Kaido 的功能规格输入，只描述规格与落地建议，不写实现代码。
>
> 术语规约（全文一致）：投入=完成任务所需的工作时间；持续时间=实际经过的工作时间；已用时间=按日历实算的时间（与工作时数无关）；相关性=任务间依赖关系；时限=对任务开始/结束日期施加的约束；分级=自动重排以均衡资源负荷；宽延=任务可推迟的余量；重要路径=决定项目总时长的相关任务链。

## 一、项目检查器（ch.2000）

### F-20-01 项目标题
- **手册依据**：项目检查器 → 标题
- **OmniPlan 行为**：设置项目名称；项目标题默认等于文稿名，但二者独立，改名互不影响。Pro 版报告使用项目标题。
- **核心数据/逻辑**：项目级字符串字段；与文件名解耦。
- **Kaido 实现方案**：`Project` 增加 `title: String` 字段；主窗口标题栏显示；不绑定到导出文件名。
- **优先级**：P2

### F-20-02 项目时间线（方向 / 日期 / 间隔）
- **手册依据**：项目检查器 → 时间线
- **OmniPlan 行为**：设置项目调度方向——固定开始时间向前排（任务尽可能早）或固定结束时间向后排（任务尽可能晚）；选择项目日期是否已确定（未确定时全部日期显示为 T 日、T+1 日……）；选择任务安排精度（分/小时/天，即「间隔」）；输入项目开始或结束日期。
- **核心数据/逻辑**：
  - `scheduleDirection: forward | backward`（影响 ASAP/ALAP 语义的全局默认）。
  - `dateMode: specific | tentative`（T 日相对日期模式）。
  - `granularity: minute | hour | day`——任务安排向上取整到该精度；改变间隔不改变投入量，只改变安排位置。
  - `projectStartDate` / `projectEndDate`。
- **Kaido 实现方案**：`Project` 增加 `scheduleDirection`、`dateMode`、`granularity`、`projectStartDate/projectEndDate` 四类字段；调度引擎以 `granularity` 作为时间离散化步长。
- **优先级**：P1（向后排程 + T 日模式可后置，P2）

### F-20-03 项目摘要
- **手册依据**：项目检查器 → 摘要
- **OmniPlan 行为**：以只读方式汇总项目信息，全部由任务数据计算得出，不可直接编辑。含总持续时间、总完成百分比、与基线的日期差异、总成本。
- **核心数据/逻辑**：
  - 总持续时间=整个项目从首任务开始到末任务结束的跨度（含工作时数日历）。
  - 完成百分比=Σ已完成投入 / Σ（已完成+剩余）投入，即按投入加权，而非任务计数。
  - 差异=实际结束日期 − 当前选定基线的结束日期；无基线时摘要基于实际日程安排。
  - 总成本=Σ资源成本（每次使用成本 × 使用次数 + 每小时成本 × 时数）+ Σ任务成本。
- **Kaido 实现方案**：`Project` 提供只读计算属性 `summary`（duration/completion/variance/cost）；详情面板或侧栏展示；完成百分比改用投入加权口径（当前 `progress` 是单任务字段，需要累加）。
- **优先级**：P2

### F-20-04 格式（货币 / 日期 / 时间单位）
- **手册依据**：项目检查器 → 格式
- **OmniPlan 行为**：定义时间与货币的显示方式：货币格式或自定义符号；日期是否显示秒/钟点；投入与持续时间的显示单位（秒/分/时/日/周/月/年）。输入不带单位的数字时按最小单位解释。显示单位过粗时出现 > / < 舍入符号。
- **核心数据/逻辑**：仅影响显示，不影响调度与计算；`displayCurrency`、`displayDatePrecision`、`displayTimeUnit`。
- **Kaido 实现方案**：`Project` 增加显示偏好字段；格式化工具类统一输出；任务详情与列表沿用该格式化。
- **优先级**：P3

### F-20-05 投入单位转换（工作周 / 转换因子）
- **手册依据**：项目检查器 → 投入单位转换
- **OmniPlan 行为**：自定义项目工作时间的标准单位：设置工作日时数与工作周时数等转换因子，决定投入如何累加到大单位；点按「编辑工作周」跳转到资源视图的「正常时数」标签编辑项目日历。
- **核心数据/逻辑**：
  - 转换因子与工作时数日历分离：转换因子只改输入/显示口径，不改实际工作时数。
  - 工作周=每周工作时数（如 6 天 × 7 时 = 42 时）；工作时数决定「一天能完成多少投入」。
  - 例：工作周 6 天、每天 7 时，则甘特图中显示需把工作日设为 7 时、工作周设为 42 时，否则显示时间不准确。
- **Kaido 实现方案**：`Project.workWeek` 保存每周工作时长（周内每日时段块列表）；`Project.effortConversion` 保存单位换算系数；调度引擎用工作时数日历把「投入」换算成「持续时间」。
- **优先级**：P1（投入↔持续时间换算的根基）

### F-20-06 文稿文件类型与预览
- **手册依据**：项目检查器 → 文稿
- **OmniPlan 行为**：选择保存为平面文件（默认，云兼容好）或包（旧版兼容）；选择保存时是否生成「快速查看」预览。
- **核心数据/逻辑**：属文件格式与性能选项，与任务语义无关。
- **Kaido 实现方案**：Kaido 无此概念，暂不落地；若未来支持导出可记为「导出格式选项」。
- **优先级**：P3

## 二、里程碑检查器（ch.2100）

### F-21-01 重要路径宽延限制
- **手册依据**：里程碑检查器 → 重要路径的宽延限制
- **OmniPlan 行为**：项目范围的值，决定任务对里程碑的紧迫程度、进而判定任务是否属重要路径；值越高，纳入重要路径的任务越多（缓冲越局促）。
- **核心数据/逻辑**：`criticalSlackLimit: Duration`——任务总宽延（总浮动）≤ 该值即判为重要路径成员；宽延=可推迟量而不影响里程碑/项目完成。
- **Kaido 实现方案**：调度引擎输出每个任务的 `totalSlack`，与 `criticalSlackLimit` 比较生成重要路径集合。
- **优先级**：P1

### F-21-02 里程碑图标与列表
- **手册依据**：里程碑检查器 → 里程碑图标
- **OmniPlan 行为**：用里程碑选择样式或项目样式颜色的图标；点按收合/展开里程碑行；处于重要路径时图标带重要路径高亮色边框。
- **核心数据/逻辑**：零长度任务的视觉表示，绑定样式系统与重要路径集合。
- **Kaido 实现方案**：任务类型为里程碑（见 F-22-01）时在列表行与详情面板使用菱形/旗帜图标；重要路径高亮时描边。
- **优先级**：P2

### F-21-03 显示重要路径
- **手册依据**：里程碑检查器 → 显示重要路径
- **OmniPlan 行为**：开关里程碑重要路径显示；该显示与各视图「视图子菜单」的重要路径选项叠加生效。
- **核心数据/逻辑**：`showCriticalPath: Bool`（里程碑级或全局视图级），渲染逻辑消费重要路径集合。
- **Kaido 实现方案**：列表行高亮 + 甘特条高亮（甘特图落地后）；视图层开关绑定该字段。
- **优先级**：P1

### F-21-04 考虑资源可用性
- **手册依据**：里程碑检查器 → 考虑资源可用性
- **OmniPlan 行为**：选中后，重要路径不仅考虑任务依赖与宽延限制，还考虑资源是否够用。示例：两独立任务共用同一资源，第一个任务完成后第二个才能开始；不选中该选项时重要路径只高亮第二个任务，选中后两个都高亮——第二个虽不依赖第一个，但受完成它所缺资源的限制。
- **核心数据/逻辑**：重要路径算法从纯依赖图扩展为「依赖 + 资源争用」：当某资源超负荷导致任务被迫串行时，把该争用边视为隐式相关性，纳入宽延计算。
- **Kaido 实现方案**：调度引擎先做资源分级（见 F-22-09/F-23），再据实际安排计算资源争用导致的串行化，并入重要路径判定。
- **优先级**：P2

### F-21-05 重要路径高亮显示颜色
- **手册依据**：里程碑检查器 → 重要路径高亮显示颜色
- **OmniPlan 行为**：为重要路径高亮选择颜色；重要路径显示开启的视图中，成员任务以该颜色高亮。
- **核心数据/逻辑**：样式配置项，绑定样式系统（见 ch.2400）。
- **Kaido 实现方案**：`Project.criticalPathColor` 或样式表项；列表/甘特共用。
- **优先级**：P3

## 三、任务检查器（ch.2200）

### F-22-01 任务信息（名称 / 类型 / 重复）
- **手册依据**：任务检查器 → 任务信息
- **OmniPlan 行为**：设置任务名称与类型；类型含四种：任务（标准工作项）、里程碑（零长度事件）、群组（承载子任务的层级父项）、吊床（持续时间随前后任务变动）。附加选项：使任务重复 / 编辑重复规则 / 停止重复；群组「关闭后显示任务条」或「关闭后向上滚动子项」。
- **核心数据/逻辑**：
  - `taskType: task | milestone | group | hammock`。
  - 里程碑无持续时间、无需投入；群组时长由其成员累计；吊床起止由前后相关性决定（详见 F-30-12 违例）。
  - 重复任务：`recurrenceRule` + 派生实例列表。
- **Kaido 实现方案**：`TaskItem` 增加 `kind: TaskKind`（默认 `.task`）；里程碑忽略持续时间计算；群组可暂以「折叠+聚合子项进度」实现；重复任务以 `recurrenceRule` 字段延后到 P2。
- **优先级**：P0（任务类型是调度语义的分支前提）

### F-22-02 已用时间任务
- **手册依据**：任务检查器 → 任务信息 → 创建带有已用时间的任务
- **OmniPlan 行为**：在持续时间/提前延隔值前键入 `e` 前缀转为已用时间（如 `48eh`=48 小时已用时间），按真实日历时间计，不受项目工作时数影响（例：周五开始晾漆 48 小时，下周一上午可继续）。已用时间任务通常无需资源。
- **核心数据/逻辑**：`timeBase: working | elapsed` 贯穿任务持续时间与相关性提前/延隔；已用时间用 7×24 连续时间轴计算。
- **Kaido 实现方案**：`TaskItem` 增加 `durationTimeBase`；相关性 `lag` 增加 `working|elapsed` 类别（见 F-22-06）；调度引擎对 elapsed 段不做工作时数裁剪。
- **优先级**：P2

### F-22-03 投入 / 持续时间 / 任务成本
- **手册依据**：任务检查器 → 任务信息
- **OmniPlan 行为**：任务信息显示投入（已完成/剩余/总投入）、持续时间、任务成本；资源成本与总成本（资源成本+任务成本）只读显示。
- **核心数据/逻辑**：
  - 投入（effort）=考虑所有资源后的总工作量；持续时间（duration）=实际工作时间；剩余=总投入−已完成。
  - 例：任务持续时间 4 小时，分配 2 个 100% 单位+效率的资源 → 投入 8 小时；反向，投入 8 小时除以 2 资源 = 持续时间 4 小时。公式：`duration = effort / Σ(units_i × efficiency_i)`。
  - 任务成本 = 任务级自定义成本；资源成本 = Σ(每次使用成本 + 每小时成本 × 时数)。
- **Kaido 实现方案**：`TaskItem` 增加 `effortEstimated`、`effortRemaining`（派生 `effortCompleted`）、`taskCost`；持续时间由调度引擎按资源分配与工作周换算并写回 `computedDuration`。当前 `progress` 保留为快捷输入，可与投入派生值互相换算。
- **优先级**：P0（投入/持续时间/成本是成本计算与负荷计算的基础）

### F-22-04 日程安排（自动/手动、时限、ASAP/ALAP、拆分、优先级）
- **手册依据**：任务检查器 → 日程安排
- **OmniPlan 行为**：任务可自动分级定位或手动设位置；自动任务开始/结束由引擎决定不可编辑，手动任务用日历输入。时限四类（每个任务可有一个开始时限与一个结束时限）：开始不早于、结束不早于、开始不晚于、结束不晚于。ASAP/ALAP 覆盖项目方向的单任务设置。允许拆分控制任务是否可被拆分。数字优先级决定分级时资源分配顺序（最高正数优先），延迟是分级自动写入的值。
- **核心数据/逻辑**：
  - `scheduleMode: automatic | manual`。
  - `startConstraint: none | notEarlierThan | notLaterThan`（日期值）+ `endConstraint: none | notEarlierThan | notLaterThan`（日期值）。
  - `asapAlap: asap | alap`（覆盖项目方向）。
  - `allowsSplitting: Bool`。
  - `priorityNumeric: Int`（分级资源分配顺序依据）；`deferredBy`（延迟，分级自动写入）。
- **Kaido 实现方案**：`TaskItem` 增加上述字段；详情面板「排期」区从单一截止日期扩展为开始/结束 + 时限 + 自动/手动开关；调度引擎在 forward pass 尊重不早于、在 backward pass 尊重不晚于。
- **Kaido 实现方案（F-14-10 / Sprint 8 已落地部分）**：检查器任务页「开始」「结束」均可编辑，点击字段弹出月历。**开始**写 `TaskItem.startDate`（用户意图锚点，可清除）；**结束**取计划结束 `scheduledFinish`（**排他端点**：1 天任务 11-02 开始 → 结束 11-03，条体覆盖 11-02 当天），编辑时保持排期起点、按 `durationDays = 结束 − 起点`（日粒度整数，下限 1 天）改写持续时间；`dueDate`（截止日期）保持独立字段与原义，不改。里程碑「结束」只读（持续时间为 0），群组只读。依赖冲突与时限违例**不阻断**写入，由违例检查呈现。见 `docs/archive/Sprint8-task-dates/design.md`。
- **优先级**：P1（自动/手动与时限是调度引擎的主要输入）

### F-22-05 基线
- **手册依据**：任务检查器 → 基线
- **OmniPlan 行为**：只读展示任务相对当前基线的预期开始/结束，以及与基线的差异。使用「设置基线」命令后出现，可切换对比的基线。
- **核心数据/逻辑**：`baselineStartDate`/`baselineEndDate` 快照；差异=实际 − 基线；支持多版本基线（当前取所选版本）。项目摘要的差异字段同源。
- **Kaido 实现方案**：`TaskItem` 增加 `baselineStartDate/baselineDueDate`；`Project` 维护 `baselines: [Baseline]`（每版本一快照）并记录 `selectedBaseline`；「设置基线」= 全量快照当前安排。
- **优先级**：P2

### F-22-06 相关性（列表 / 编辑器 / 提前与延隔）
- **手册依据**：任务检查器 → 相关性、相关性编辑器
- **OmniPlan 行为**：列出被检查任务的相关性，分「必要条件」（本任务依赖的前驱）与「相关性」（依赖本任务的后继）；可添加/删除/编辑，每条可设类型与提前/延隔时间。相关性编辑器可切换必要条件/相关性方向、改类型、设提前/延隔（工作时间/已用时间/百分比）。
- **核心数据/逻辑**：
  - 有向边 `predecessor → successor`，带 `type: FS|FF|SS|SF` 与 `lag`。
  - 提前时间（lead，正值）＝后任务相对前任务提前开始/结束；延隔时间（lag，负值语义相反）。文档示例：SS + 1 天前导 = 前任务开始 1 天后后任务才开始；FS − 2 小时前导 = 前任务还剩 2 小时时后任务即可开始。
  - lag 单位三种：工作时间、已用时间、前任务持续时间的百分比。
  - 在任务大纲可透过输入持续时间（如 `+3周`、`-2天 4时`）设置。
- **Kaido 实现方案**：将 `TaskItem.dependencies: [UUID]` 重构为 `dependencies: [TaskDependency]`，其中 `TaskDependency { predecessorID: UUID, type: DependencyType, lag: Lag }`；`Lag { amount: Double, unit: working|elapsed|percentage }`。现有代码以「前置必须完成」语义（FS、无 lag）迁移兼容。详情面板依赖区增加类型与 lag 编辑。
- **优先级**：P0（调度图的核心数据结构；当前模型只有隐式 FS）

### F-22-07 相关性类型（FS / FF / SS / SF）
- **手册依据**：任务检查器 → 相关性 → 相关性类型
- **OmniPlan 行为**：四种相关性类型：
  - 完成到开始（FS）：前任务结束、后任务才能开始；不能重叠。默认类型，工具栏「连接任务」按钮生成此类型。
  - 完成到完成（FF）：前任务结束后、后任务才能结束；允许重叠。
  - 开始到开始（SS）：前任务开始后、后任务才能开始；允许重叠。
  - 开始到完成（SF）：前任务开始后、后任务才能完成；必须重叠（至少在前任务开始的瞬间）。
- **核心数据/逻辑**：调度引擎时间传播规则：
  - FS：`succStart ≥ predFinish + lag`。
  - FF：`succFinish ≥ predFinish + lag`。
  - SS：`succStart ≥ predStart + lag`。
  - SF：`succFinish ≥ predStart + lag`。
  - 前向/后向传递时分别以上述不等式更新最早/最晚时间。
- **Kaido 实现方案**：`DependencyType` 枚举（`.finishToStart/.finishToFinish/.startToStart/.startToFinish`）；调度引擎核心函数按类型计算约束时间；甘特连线样式按类型区分（落地甘特时）。
- **优先级**：P0（调度引擎的核心语义；若首版只做 FS 也须预留类型字段）

### F-22-08 分配的资源
- **手册依据**：任务检查器 → 分配的资源
- **OmniPlan 行为**：查看任务分配的资源；调整某资源贡献的投入量（单位百分比）；添加/删除资源。素材资源单位表示用量。资源群组被分配时仅作信息性标记（无投入属性、不可直接删除）。
- **核心数据/逻辑**：任务↔资源多对多分配 `TaskAssignment { resourceID, units }`；`units` 以资源总投入百分比表示，不超过资源可用上限；素材的 units 为数量。
- **Kaido 实现方案**：新建 `Resource` 模型与 `TaskAssignment`；`TaskItem.assignee: String?` 保留为便捷显示，内部映射到 person 资源。任务详情「负责人」区升级为资源分配列表（多资源 + 单位滑块）。
- **优先级**：P1

### F-22-09 资源分配模式（调整持续时间 / 工作量 / 已分配额度）
- **手册依据**：任务检查器 → 资源分配
- **OmniPlan 行为**：增删资源时三种调度模式：
  - 调整任务持续时间：资源增 → 持续时间缩短，投入不变。
  - 调整任务工作量：资源增 → 持续时间不变，投入增加（固定期间密集投入）；删资源 → 总投入减少。
  - 调整已分配的额度：持续与投入都不变，资源各自单位均匀分摊（1 个 100%、2 个各 50%……）。
- **核心数据/逻辑**：模式决定增删资源后投入/持续时间/单位三者的守恒关系；本质是 `effort = duration × Σ(units_i × efficiency_i)` 中固定哪个变量。
- **Kaido 实现方案**：`TaskAssignmentMode` 枚举；增删资源入口按所选模式重算。默认用「调整持续时间」。
- **优先级**：P1

### F-22-10 任务进度需要（任何 / 所有分配的资源，会议建模）
- **手册依据**：任务检查器 → 资源分配 → 任务进度需要、日程安排会议
- **OmniPlan 行为**：选择「任何分配的资源」= 任一可用资源即可推进任务；选择「所有分配的资源」= 所有被分配资源都可用才安排任务。后者用于建模会议：只有全体与会人员可用时才安排（固定时间会议则围绕它安排其他任务）。
- **核心数据/逻辑**：`progressRequirement: anyAssigned | allAssigned`；分级与调度引擎在资源可用性检查时按此聚合（AND 而非 OR）。
- **Kaido 实现方案**：`TaskItem` 增加 `requiresAllAssignees: Bool`；分级算法的资源窗口计算分支处理。
- **优先级**：P2

### F-22-11 估算投入量（Monte Carlo，Pro）
- **手册依据**：任务检查器 → 估算投入量（Pro）
- **OmniPlan 行为**：为 Monte Carlo 模拟设置预计/最小/最大三个投入值，预测里程碑按时完成的概率。加权平均公式：(最小 + 4×预计 + 最大) / 6；全应用投入值（大纲投入栏、任务信息投入字段）均按此三值均值计算。工具栏「模拟」自动估算所选任务的投入范围。
- **核心数据/逻辑**：`effortMin/effortExpected/effortMax`；`weightedMean = (min + 4×expected + max) / 6`；Monte Carlo 多次随机采样（每次结果略不同）给出信心百分比。
- **Kaido 实现方案**：`TaskItem` 增加三个估算字段与派生 `effort`（加权均值）；预测能力（模拟仪表）作为 P3 进阶，先落地三字段存储与均值派生。
- **优先级**：P3（进阶预测；三字段存储可 P2）

### F-22-12 安排影响因素
- **手册依据**：任务检查器 → 安排影响因素
- **OmniPlan 行为**：列出当前影响自动安排任务的所有因素：资源可用性、相关性、任务与项目的开始/结束时限；连按某项导航到对应检查器字段，点按齿轮菜单可直接编辑。
- **核心数据/逻辑**：调度引擎的可解释性输出——把影响任务的约束边归因列表化（原因→字段）。
- **Kaido 实现方案**：调度引擎为每个任务输出 `schedulingFactors: [Factor]`（factor kind + 来源 taskID/字段 + 影响值）；详情面板只读列表展示。
- **优先级**：P2

## 四、资源检查器（ch.2300）

- **手册依据**：资源检查器 → 资源信息
- **OmniPlan 行为**：配置资源描述信息：名称、电子邮件（人员跨项目标识，可关联 macOS 地址簿）、类型（人员/工具/素材/群组）、单位（人员/工具为可用投入百分比，素材为用量）、效率、可用开始/结束日期、每次使用成本与每小时成本；总使用次数/总时数/总成本只读汇总。

- **Kaido 实现方案**：资源详情面板内嵌任务分配列表；点按任务行定位并选中主列表对应行（复用 `ContentView` 的 `selectedTaskID`/`scrollTargetID` 机制）。
- **优先级**：P1

## 七、违例解决（ch.3000）

### F-30-01 违例窗口
- **手册依据**：解决违例
- **OmniPlan 行为**：项目出现逻辑违例时，任务大纲违例栏/甘特违例栏显示红色图标，点击或按 Shift-Command-V 打开违例窗口；窗口列出全部违例并附原因说明，多数说明带「立即解决」链接，底部提示辅助手动定位根因。
- **核心数据/逻辑**：违例引擎在每次安排变更后对全项目跑规则集，产出 `[Violation { kind, message, affectedTaskIDs, autoFix }]`；违例栏图标 = 违规任务标记。
- **Kaido 实现方案**：`Project.violations: [Violation]` 由调度引擎在每次模型变更后重算；列表行违规任务加红点图标；点击展开违例明细面板。
- **优先级**：P1

### F-30-02 错误：指定的资源多于可用资源
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：分配给任务的资源数量超过项目可用资源（X 已分配共计 Y）。
- **调度语义**：资源不存在或已删除时残留分配；发生条件=分配的 `resourceID` 在 `Project.resources` 无对应项。自动解决=从任务移除悬空分配；手动=补建资源或删分配。
- **Kaido 实现方案**：分配引用完整性校验规则；自动修复=清理悬空 `TaskAssignment`。
- **优先级**：P1

### F-30-03 错误：时限靠得太近
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务的开始时限与结束时限相距过近，无法容纳整个任务持续时间。
- **调度语义**：`(endConstraintDate − startConstraintDate) < 任务最小持续时间`（按工作时数/投入换算）；发生条件=用户设置了互相冲突的开始/结束时限。自动解决=放宽其中一个时限（移除较新的）；手动=调整时限或缩短任务。
- **Kaido 实现方案**：校验 `startConstraint`/`endConstraint` 与 `computedDuration` 的相容性。
- **优先级**：P1

### F-30-04 错误：X 时限是先决条件
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：由于先决条件（前驱任务），任务无法在其开始时限（不早于/不晚于）规定的日期或之前开始。
- **调度语义**：前向传递后 `earliestStart(由前驱推算) > startConstraintDate`，与「开始不晚于」时限冲突；或后向传递后前驱链把开始时间推到时限之后。自动解决=移除冲突时限或调整前驱；手动=检查前驱时长与时限。
- **Kaido 实现方案**：调度后对比 `earliestStart` 与时限；冲突时标记并建议解除。
- **优先级**：P1

### F-30-05 错误：X 时限是相关性
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务可能的结束日期减去其持续时间，使任务能够在其开始时限之前开始（时限与相关性冲突）。
- **调度语义**：`possibleFinish − duration < startConstraintDate`——相关性链把结束时间压得过早，与「开始不早于」时限冲突。自动解决=调整时限或相关性 lag；手动=拆限时/相关性。
- **Kaido 实现方案**：校验相关性约束推导的 `latestStart` 是否早于「开始不早于」时限。
- **优先级**：P1

### F-30-06 错误：无法安排 ASAP/ALAP 任务
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：尽可能晚（ALAP）任务无法安排，因为其先决条件与从属任务之间没有足够时间。
- **调度语义**：前后向传递出现空档（`latestStart < earliestStart` 或区间冲突），ASAP/ALAP 与项目方向不一致时产生。自动解决=改回项目方向或调 lag；手动=重新排相关任务。
- **Kaido 实现方案**：传递后检测负浮动（`slack < 0`）任务。
- **优先级**：P1

### F-30-07 错误：任务结束于群组的结束时限日期之后
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：子任务的安排结束日期迟于所属群组的结束时限。
- **调度语义**：群组（父项）结束时限约束成员任务的结束时间；子任务时长溢出父约束。自动解决=压缩子任务或后移群组时限；手动=调整子任务或群组。
- **Kaido 实现方案**：层级约束校验（群组模式下）；平铺模型下该规则暂退化。
- **优先级**：P1

### F-30-08 错误：此任务与某个相关性循环有联系
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务处于相关性环中；为避免死循环，系统停用了该环中的一条相关性（如任务 X 到 Y 的相关性）。
- **调度语义**：依赖图出现环时无法做拓扑排序；发生条件=新增相关性形成环。自动解决=停用构成环的最后一条边（并记录）；手动=删除/改向某条边。检测算法=DFS 拓扑排序找环。
- **Kaido 实现方案**：添加相关性时先做环检测（DFS）；发现环则拒绝或提示停用边。当前 `dependencies:[UUID]` 已是图结构，重构后加环检测。
- **优先级**：P1

### F-30-09 错误：吊床任务没有开始和结束先决条件
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：吊床任务缺少与其开始及结束相关的相关性，持续时间不确定。
- **调度语义**：吊床时长 = 上一任务完成至下一任务开始之间的可变区间；缺少任一侧锚定则时长不可计算。自动解决=提示补相关性；手动=添加前驱/后继。
- **Kaido 实现方案**：`kind == .hammock` 时校验前后相关性是否齐全。
- **优先级**：P2

### F-30-10 错误：手动日期设置在完成必要条件前
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务被设为手动安排，但其必要条件（前驱）尚未完成，无法在当前日期开始。
- **调度语义**：手动任务忽略引擎自动定位，但前驱 FS 约束仍强制 `start ≥ 前驱完成`；手动日期早于该下限即违例。自动解决=把任务改回自动安排或后移手动日期。
- **Kaido 实现方案**：手动任务校验 `startDate ≥ 所有前驱完成时间`。
- **优先级**：P1

### F-30-11 错误：手动日期设置早于不早于时限日期
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务设为手动日期，但无法在当前日期开始，因为「开始不早于」时限要求更晚开始。
- **调度语义**：`manualStart < startConstraintDate`（notEarlierThan 时限）。自动解决=后移手动日期至时限；手动=调整时限。
- **Kaido 实现方案**：手动任务校验 `startDate ≥ notEarlierThan 时限值`。
- **优先级**：P1

### F-30-12 错误：预计的时间超出资源工作时间
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：剩余工作时间不足以让被分配资源完成任务。
- **调度语义**：`Σ 资源在任务区间的可用投入 < 任务剩余投入`——资源工作时间日历或可用期（availabilityStart/End）不足以容纳剩余工作量。自动解决=延长任务或增加资源；手动=调整分配/资源可用期。
- **Kaido 实现方案**：按工作周日历累加资源可用投入，与 `effortRemaining` 对比。
- **优先级**：P1

### F-30-13 错误：任务结束于项目的结束日期之后
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务的安排结束日期迟于项目结束日期。
- **调度语义**：后向传播或用户输入使 `finish > projectEndDate`（固定结束日期项目）。自动解决=压缩任务或后移项目结束日期；手动=调整。
- **Kaido 实现方案**：校验每个任务 `finish ≤ projectEndDate`。
- **优先级**：P1

### F-30-14 错误：任务开始于项目的开始日期之前
- **手册依据**：违例类型 → 错误
- **OmniPlan 行为**：任务的安排开始日期早于项目开始日期。
- **调度语义**：`start < projectStartDate`（固定开始日期项目）。自动解决=后移任务或前移项目开始日期；手动=调整。
- **Kaido 实现方案**：校验每个任务 `start ≥ projectStartDate`。
- **优先级**：P1

### F-30-15 警告：无法在资源分级期间适应任务
- **手册依据**：违例类型 → 警告
- **OmniPlan 行为**：任务无法被完全分级，分配的资源可能超负荷；任务未移动。分级失败原因=执行时间不够且需同时遵守全部限制。
- **调度语义**：资源负荷（某时段 Σ 分配投入 > 资源可用量）无法在时限/相关性约束内消除；分级算法尝试后仍超负荷。自动解决=调整资源单位或延长任务；手动=改约束。
- **Kaido 实现方案**：分级算法（见 F-22-09）输出超负荷任务清单；与 F-21-04 的资源争用数据同源。
- **优先级**：P1

### F-30-16 警告：已超过最大努力程度
- **手册依据**：违例类型 → 警告
- **OmniPlan 行为**：单个任务投入超过 OmniPlan 上限（20 年或 100 人-年）；可能由直接输入或文件损坏导致。
- **调度语义**：投入边界校验 `effort ≤ min(20年, 100人-年)`。自动解决=无（提示修正数据）。
- **Kaido 实现方案**：投入字段写入门禁校验上限。
- **优先级**：P2

### F-30-17 警告：从 OmniPlan 1.x 预留丢失的时间
- **手册依据**：违例类型 → 警告
- **OmniPlan 行为**：群组含 OmniPlan 1.x 的预留时间属性，当前版本已不存在该属性，值已丢失，其余安排信息不受影响。
- **调度语义**：旧格式兼容性警告；Kaido 无历史格式，不适用。
- **Kaido 实现方案**：不落地；若未来有迁移导入可预留「迁移警告」机制。
- **优先级**：P3

### 落地顺序建议（P0 先行，支撑后续）

1. **依赖模型重构**（F-22-07）：`dependencies: [UUID]` → `[TaskDependency]`（含类型与 lag），当前语义迁移为 FS、无 lag。
2. **任务类型与投入模型**（F-22-01、F-22-03）：`kind` 字段 + 投入/持续时间/成本字段。
3. **资源模型**（F-23-01）：`Resource` + `TaskAssignment`，替换 `assignee: String?`。
4. **工作周日历与换算**（F-20-05）：投入↔持续时间换算、工作时数日历。
5. **调度引擎**（由 F-22-04/F-22-07/F-22-09 驱动）：前后向传递（FS/FF/SS/SF + lag）、时限、ASAP/ALAP、资源分级。
6. **违例引擎**（F-30-*）：在调度引擎之上跑规则集，输出违例列表。
7. **重要路径**（F-21-01/03/04）：消费调度引擎的浮动值与分级结果。
