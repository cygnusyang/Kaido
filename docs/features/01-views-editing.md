# 一、视图与编辑功能拆解（OmniPlan 手册 ch.11–16）

> 来源：OmniPlan 4.1.2 macOS 版内置手册（zh-Hans，章节 1100–1600：创建项目 / 文稿工具栏 / 项目大纲视图 / 甘特视图 / 网络视图 / 资源视图）。
> 本文件为 Kairo 的功能规格输入，只描述规格，不含实现代码。
> 术语约定：沿用 OmniPlan 术语「任务 / 群组（组）/ 里程碑 / 资源 / 相关性 / 基线 / 时限 / 宽延」，映射到 Kairo 时在「Kairo 实现方案」中给出对应字段或组件。

## 第 11 章 创建项目

### F-11-01 新建项目协助（New Project Assistant）
- **手册依据**：第11章「使用新的项目协助」
- **OmniPlan 行为**：文件 > 新建项目（Command-N）打开一个向导窗口，一次收集新项目的初始设置：模板、排程方向、排程间隔、开始/结束日期、资源分级模式。确认后生成新文稿，可按需继续修改。
- **核心数据/逻辑**：新项目初始配置对象：模板引用、方向（向前/向后）、间隔精度（秒级/舍入）、项目开始或结束日期、资源分级模式（自动/按需）。
- **Kairo 实现方案**：新增 `ProjectSettings`（方向、间隔精度、自动分级开关）挂到 `Project`。新建项目时弹出配置表单（SwiftUI sheet），初始值写入 `Project`。Kairo 当前以任务列表为主体，向导默认提供「空项目」即可，配置项可作为进阶。
- **优先级**：P1

### F-11-02 项目方向（向前 / 向后排程）
- **手册依据**：第11章「使用新的项目协助」→ 方向；项目检查器对应设置
- **OmniPlan 行为**：项目要么从固定开始日期向前排程，要么从固定结束日期向后排程。方向决定任务日期如何由分级算法推导。
- **核心数据/逻辑**：`direction: forward | backward` + 锚点日期（startDate 或 dueDate）；排程时从锚点沿依赖链前推或后推。
- **Kairo 实现方案**：`ProjectSettings.direction` 枚举字段。Kairo 暂无自动排程，可先只支持 `forward`（任务日期由用户/依赖推导），`backward` 作为排程引擎的输入，P2 再做引擎。
- **优先级**：P2

### F-11-03 排程间隔精度
- **手册依据**：第11章「使用新的项目协助」→ 间隔
- **OmniPlan 行为**：选择任务精确排程（精确到秒）或带某种程度的舍入（如整日/整小时）。影响任务开始/结束时间的显示与计算粒度。
- **核心数据/逻辑**：`interval: exact | rounded(单位)`；时间计算按单位取整。
- **Kairo 实现方案**：`ProjectSettings.schedulePrecision`（`.exact` / `.day` / `.hour`）。甘特/大纲显示层按精度格式化日期；Kairo 已有 `Date?`，默认 `.day` 即可。
- **优先级**：P2

### F-11-04 模板系统（内置 + 自定义 + 默认）
- **手册依据**：第11章「内置模板」「创建模板」
- **OmniPlan 行为**：模板是存为项目底稿的文件，保存了内容、检查器状态、显示栏、样式、工作时数等一切设置。内置三个模板（简单项目 / 标准项目 / 标准项目·样式化）；自定义模板通过「另存为模板」创建，可在偏好设置中编辑、删除或设为默认。
- **核心数据/逻辑**：模板 = 序列化的 `Project` 快照（含内容与元数据）；模板文件列表 + 默认模板引用。
- **Kairo 实现方案**：`Project` 已 Codable，可直接把当前项目序列化为模板（存到 App 支持目录）。提供「另存为模板」菜单与模板选择列表。内置模板可作为 `SeedData` 变体。
- **优先级**：P2

### F-11-05 保存位置与协作考量
- **手册依据**：第11章「选择保存位置」
- **OmniPlan 行为**：macOS 沙盒限制外保存的文件无法用 OmniPlan URL 链接访问；保存位置需考虑云存储与多用户协作。
- **核心数据/逻辑**：项目文件持久化路径 + 链接可用性。
- **Kairo 实现方案**：Kairo 使用标准文档存储或 UserDefaults 持久化即可；若做外部文件链接，遵循沙盒安全作用域（security-scoped bookmark）。此条为工程约束说明，不作为独立功能。
- **优先级**：P3

### F-11-06 深色模式自动适配
- **手册依据**：第11章「macOS 暗黑模式下的 OmniPlan 文稿」
- **OmniPlan 行为**：默认模板创建的新文稿随 macOS 外观设置自动切换颜色主题，不再依赖特定模板。
- **核心数据/逻辑**：主题跟随系统 `colorScheme`。
- **Kairo 实现方案**：SwiftUI 视图全部使用语义色（`Color(.textColor)` 等）即自动适配，无需额外存储。
- **优先级**：P3

## 第 12 章 文稿工具栏

### F-12-01 自定工具栏
- **手册依据**：第12章「自定工具栏」「空间」「活动空间」
- **OmniPlan 行为**：查看 > 自定义工具栏打开表单，可增删按钮、调整间距与显示方式；更改一致应用到所有文稿。空间框 = 固定宽度间隔；活动空间框 = 按窗口宽度缩放的可变间隔。
- **核心数据/逻辑**：工具栏项集合（按钮标识 + 顺序 + 间隔类型）。
- **Kairo 实现方案**：SwiftUI `ToolbarItem` 可配置列表，持久化到 `UserDefaults`。空间/活动空间对应自定义 `ToolbarItem(placement: .automatic)` 的 spacer 变体。Kairo 工具栏当前较简单，此项 P2。
- **优先级**：P2

### F-12-02 视图切换器（四视图）
- **手册依据**：第12章「视图」
- **OmniPlan 行为**：视图切换器在项目大纲、甘特、网络、资源四种视图间切换（Option-Command-1..4）。
- **核心数据/逻辑**：当前视图模式枚举 + 各视图共享同一 `Project` 数据源。
- **Kairo 实现方案**（2026-10-18 重设计）：Kairo 主窗口为计划工作台，不再是四视图切换容器。视图模式定名为**计划**与**大纲**：计划模式并排显示大纲、时间画布与检查器；大纲模式显示全宽大纲。快捷键 `⌥⌘1` 计划、`⌥⌘2` 大纲、`⌥⌘L` 图表聚焦。启动固定进入计划模式，模式不跨会话持久化。网络与资源视图不在本期范围。规格见 [ui-redesign](../design/ui-redesign.md) §2。
- **优先级**：P1

### F-12-03 重要路径开关
- **手册依据**：第12章「重要路径」
- **OmniPlan 行为**：显示/隐藏里程碑的重要路径；下拉菜单选择对哪些里程碑显示。只在甘特图中生效。
- **核心数据/逻辑**：关键路径计算（见 F-14-15）+ 选中里程碑集合。
- **Kairo 实现方案**（2026-10-18 重设计）：重要路径始终由核心计算（状态栏计数需要），画布显示默认关闭；开关只影响绘制。开启后任务条描边与依赖线使用品牌紫 `critical.graphic`，状态栏显示数量与图例。红色只用于错误与逾期。见 [DESIGN.md](../DESIGN.md) §2.2。
- **优先级**：P2

### F-12-04 过滤器入口
- **手册依据**：第12章「过滤器」
- **OmniPlan 行为**：创建/应用自定义过滤器；应用后仅显示符合条件的任务，视图顶部出现过滤通知栏（含编辑/删除/刷新选项与隐藏任务数）。
- **核心数据/逻辑**：过滤器对象（条件树）+ 当前激活过滤器；过滤期间只允许编辑可见任务。
- **Kairo 实现方案**（2026-10-18 重设计）：筛选栏高 32，可收起，包含自然语言输入、筛选令牌与查找入口。筛选激活时，命中任务的祖先链必须强制可见并展开；退出筛选恢复用户原有展开状态。聚合始终基于全量子树，过滤只影响可见性。筛选期间禁用拖拽重排；定位被筛选隐藏的任务时临时清除筛选并提示。筛选条件不跨会话持久化；可保存过滤器不在本期范围。见 [ui-redesign](../design/ui-redesign.md) §4.3。
- **优先级**：P0

### F-12-05 分级（Level Resources）
- **手册依据**：第12章「分级」
- **OmniPlan 行为**：以编程方式重新安排任务以获得最佳效率，主要解决资源冲突与依赖顺排。
- **核心数据/逻辑**：排程算法（拓扑序 + 资源冲突消解 + 优先级/时限约束）。
- **Kairo 实现方案**：独立的调度器（纯函数，输入 `Project` 输出新日期安排）。Kairo 现无资源模型，依赖资源视图落地，此项 P3。
- **优先级**：P3

### F-12-06 同步更新任务完成情况
- **手册依据**：第12章「同步更新」；第14章「更新任务完成情况」
- **OmniPlan 行为**：把任务完成情况批量更新到当前日（或指定日期），可选部分完成、更新全部或所选任务。
- **核心数据/逻辑**：按 `progress` 与完成百分比分布到日期；更新 `progress` 与 `completionDate`。
- **Kairo 实现方案**：工具栏按钮弹确认表单（目标日期、范围），把所选/全部任务 `progress` 推进并按日期记 `completedAt`。Kairo 的 `progress: Double` 已具备，此项 P1。
- **优先级**：P1

### F-12-07 重新安排未完成任务
- **手册依据**：第12章「重新安排」；第14章「重新安排未完成的任务」
- **OmniPlan 行为**：把截至指定日期应完成而未完成的任务移动到该日期之后继续，整个日程随之更新，不影响后续任务。
- **核心数据/逻辑**：找出「截止日期前未完成」任务 → 顺延其 `startDate`/`dueDate`（及依赖链）。
- **Kairo 实现方案**：`Project` 上提供 `reschedule(incompleteBefore: Date)` 方法，遍历未完成任务顺延日期，依赖链上的后继任务联动。
- **优先级**：P2

### F-12-08 添加任务族（添加 / 添加子项 / 添加相关性 / 添加里程碑 / 移去）
- **手册依据**：第12章「添加」「添加子项」「添加相关性」「添加里程碑」「移去」
- **OmniPlan 行为**：添加 = 在选中项下方创建同级任务；添加子项 = 在选中项下创建子任务并使其成为群组；添加相关性 = 新建任务并以完成>开始相关性连到选中任务；添加里程碑 = 创建新里程碑；移去 = 删除选中项。
- **核心数据/逻辑**：`Project.add` + 插入位置（选中项后）+ 层级（父/子）+ 依赖边 + `kind: task|milestone|group`。
- **Kairo 实现方案**：`Project` 已有 `add/update/remove`；补充 `insertAfter(id:task)`、`addChild(to:task)`（需引入 `parentID`，见 F-14-03）、`addMilestone()`（`TaskItem.kind = .milestone`）、`addTaskWithFSDependency(to:)`（构造 `dependencies` 边）。
- **优先级**：P0

### F-12-09 群组与拆分
- **手册依据**：第12章「群组」「拆分」
- **OmniPlan 行为**：群组 = 把所选任务放进新群组；拆分 = 把所选任务拆成两段（中断后继续）。
- **核心数据/逻辑**：群组：建父任务 + 重挂子任务；拆分：一条任务 → 多段带中断区间。
- **Kairo 实现方案**：群组依赖层级模型（F-14-03），P1；拆分需拆分区间字段（`intervals: [TaskInterval]`），P3。
- **优先级**：P1

### F-12-10 连接与断开任务
- **手册依据**：第12章「连接任务」「断开任务」
- **OmniPlan 行为**：连接 = 在所选任务间建完成>开始相关性（下拉可选其他类型）；断开 = 移除所选任务间的相关性。
- **核心数据/逻辑**：`dependencies` 边集合 + 相关性类型（FS/SS/FF/SF）。
- **Kairo 实现方案**：Kairo 已有 `dependencies: [UUID]`（隐式 FS）。扩展为带类型的 `TaskDependency(sourceID:type:)` 结构体数组；工具栏提供连接/断开。
- **优先级**：P1

### F-12-11 分配资源
- **手册依据**：第12章「分配」
- **OmniPlan 行为**：为所选任务检查和设置资源分配。
- **核心数据/逻辑**：任务 ↔ 资源多对多分配表（单位数）。
- **Kairo 实现方案**：引入 `Resource` 模型（见第16章），`TaskItem` 增加 `resourceAssignments: [ResourceAssignment(resourceID:units:)]`；替换/并存现有 `assignee: String?`。
- **优先级**：P1

### F-12-12 检查器与违例开关
- **手册依据**：第12章「检查」「违例」
- **OmniPlan 行为**：检查 = 显示/隐藏右侧检查器；违例 = 显示/隐藏违例窗口（列出排程矛盾）。
- **核心数据/逻辑**：检查器可见性 + 违例检测结果列表。
- **Kairo 实现方案**（2026-10-18 重设计）：检查器作为工作台右栏常驻，可开关、可拖动宽度，顶部标签页为「检查器 | 违例 N」。违例并入检查器标签页，取消底部 180pt 面板。入口为工具栏徽标、`⌥⌘V` 与整行/整条选择；行内违例图标与条尾三角只作显示。锁定为视图状态 `inspectorLocked`，不写入任务模型。窗口 820–1119 宽时检查器以 300pt 浮层打开。见 [ui-redesign](../design/ui-redesign.md) §6。
- **优先级**：P1

### F-12-13 文稿概览
- **手册依据**：第12章「文稿概览」
- **OmniPlan 行为**：工具栏下方的水平浓缩甘特条，任何视图下可见；甘特/资源视图中提供可拖动的选择框在主视图中滚动。
- **核心数据/逻辑**：`Project` 的日期跨度 → 迷你时间轴。
- **Kairo 实现方案**：甘特视图配套组件（P2）；Kairo 无独立视图时暂缓。
- **优先级**：P3

### F-12-14 自定义 Touch Bar
- **手册依据**：第12章「自定义 Touch Bar」
- **OmniPlan 行为**：Touch Bar 按视图/选中态自适应显示资源分配、分级、同步更新等控件；资源条以白色刻度/绿蓝红条表示分配与超负荷。
- **核心数据/逻辑**：Touch Bar 上下文控件映射。
- **Kairo 实现方案**：macOS 可配置 `touchBar` 属性；对 Kairo 价值低，P3。
- **优先级**：P3

### F-12-15 样式与输出（字体 / 颜色 / 打印）
- **手册依据**：第12章「字体」「颜色」「打印」
- **OmniPlan 行为**：字体/颜色按钮打开系统面板为样式属性设置字体与颜色；打印按钮打开打印对话框。
- **核心数据/逻辑**：样式属性（字体/颜色）+ 打印导出。
- **Kairo 实现方案**：Kairo 可加「导出 / 打印」菜单（NSPrintOperation 或 PDF 导出），P3。
- **优先级**：P3

### F-12-16 协作与自动化（发布 / 刷新 / 跟踪更改 / 模拟 / 报告 / 控制台，Pro）
- **手册依据**：第12章「发布」「刷新」「模拟」「报告」「跟踪更改」「显示控制台」
- **OmniPlan 行为**：Pro 功能——发布/刷新把本地改动推送到共享同步库或拉回；模拟 = 按估算投入运行 Monte Carlo（见 F-14-17）；报告 = 打开报告窗口；跟踪更改记录协作者改动；控制台打开 JavaScript 自动化环境。
- **核心数据/逻辑**：同步库 + 变更日志 + 模拟/报告入口 + 脚本运行时。
- **Kairo 实现方案**：Kairo 单机应用，此组功能 P3；模拟/报告复用 F-14-17 与远期报表模块；仅预留扩展点（如 `Project` 增加 `updatedAt`/`changedBy` 字段）。
- **优先级**：P3

### F-12-17 基线与实际（设置基线 / 基线·实际菜单）
- **手册依据**：第12章「基线/实际」「设置基线」；第14章「通过基线衡量进度」
- **OmniPlan 行为**：设置基线 = 对当前项目进度做快照以便日后对比（默认名 = 今日日期）；基线/实际菜单选择以「实际」或某个基线作为查看基准，分割/双日程模式并排比较。
- **核心数据/逻辑**：基线快照集合（见 F-14-16）+ 当前查看基准选择。
- **Kairo 实现方案**：工具栏「设置基线」调用 F-14-16 的快照逻辑；「基线/实际」菜单切换显示基准。Kairo 补基线模型后可用。
- **优先级**：P2

## 第 13 章 项目大纲视图

### F-13-01 创建和删除任务
- **手册依据**：第13章「创建和删除任务」
- **OmniPlan 行为**：Return（或 Command-Return）在选中项后新建项；工具栏「添加」；Control-点按情境菜单添加/删除；Delete 或「移去」删除。
- **核心数据/逻辑**：大纲插入位置与删除逻辑。
- **Kairo 实现方案**：Kairo `ContentView` 的 `List` 增加 Return 新建、Delete 删除、情境菜单；选中项 `selectedTaskID` 决定插入位置。
- **优先级**：P0

### F-13-02 自定义大纲栏
- **手册依据**：第13章「项目大纲栏」总述
- **OmniPlan 行为**：Control-点按大纲标头或查看 > 任务大纲 > 自定义栏选择显示栏；栏可拖移重排；方向键/Tab/Shift-Tab 单元格间移动；结构 > 排序对选中项排序。可编辑的值对应检查器可编辑字段，其余自动计算。
- **核心数据/逻辑**：显示栏配置（栏类型有序列表）+ 单元格编辑能力标记。
- **Kairo 实现方案**：SwiftUI `Table` 的列配置动态化，栏类型枚举 + 默认列集 + 顺序持久化；沿用 Kairo 数据驱动渲染思路。
- **优先级**：P1

### F-13-03 基础栏位（违例 / 状态 / 附件 / 备注 / 唯一 ID / 标题 / 分层标题）
- **手册依据**：第13章「项目大纲栏」→ 违例、状态、附件、备注、唯一 ID、标题、分层标题
- **OmniPlan 行为**：违例栏显示有违例任务的图标（点按开违例窗口）；状态栏按剩余工作天数为未完成任务显示时钟图标（绿=3 个工作日后到期、黄=1 个工作日后、红=已过期；未确定开始日期时不显示）；附件栏管理文件链接；备注栏存放额外文本（Command-‘ 编辑）；唯一 ID 永久不变、跨导入导出匹配用；标题带层级编号；分层标题用冒号串联所有上级标题。
- **核心数据/逻辑**：到期预警依赖 `dueDate` + 工作日历；`uniqueID` 持久字段；附件路径列表；备注文本；层级路径。
- **Kairo 实现方案**：`TaskItem` 已有 `id/notes/dueDate`；新增 `attachments: [URL]`、`uniqueID: Int`（或直接用 UUID 展示）、`parentID: UUID?`（层级）；状态栏按 `isOverdue`（已有）扩展「N 天内到期」计算。分层标题由父链拼接。
- **优先级**：P0

### F-13-04 时间与投入栏位（持续时间 / 投入 / 完成的投入 / 剩余的投入 / 开始 / 结束 / 已完成）
- **手册依据**：第13章「项目大纲栏」→ 持续时间、投入、完成的投入、剩余的投入、开始、结束、已完成
- **OmniPlan 行为**：持续时间 = 任务时长；投入 = 完成任务所需总投入量；完成的/剩余的投入按进度拆分；开始/结束 = 实际（或自动分级确定）时间；已完成 = 完成工作量百分比（可编辑）。
- **核心数据/逻辑**：`duration`、`effort`（投入小时）、`effortCompleted = effort × progress`、`effortRemaining = effort − effortCompleted`、`startDate`/`dueDate`、`progress`。
- **Kairo 实现方案**：`TaskItem` 新增 `duration: TimeInterval?`、`effort: Double?`；`progress` 已有；「已完成」栏直接编辑 `progress`，「开始/结束」编辑 `startDate/dueDate`。持续时间与投入做计算列。
- **优先级**：P0（开始/结束/已完成）/ P1（持续时间/投入族）

### F-13-05 相关性栏位（先决条件 / 相关性）
- **手册依据**：第13章「项目大纲栏」→ 先决条件、相关性
- **OmniPlan 行为**：先决条件栏列出本任务依赖的任务编号（带相关性类型代码）；相关性栏列出依赖本任务的任务编号。
- **核心数据/逻辑**：依赖边（sourceID + type）与反查（successors）。
- **Kairo 实现方案**：基于 F-12-10 的类型化依赖结构；`Project` 提供 `predecessors(of:)` / `successors(of:)` 查询。栏内以「任务编号+类型码」文本展示，可输入编辑。
- **优先级**：P1

### F-13-06 优先级与分配栏位（优先级 / 已分配）
- **手册依据**：第13章「项目大纲栏」→ 优先级、已分配
- **OmniPlan 行为**：优先级手动设置，控制分级时资源冲突的分配顺序；已分配栏列出任务分配到的资源列表。
- **核心数据/逻辑**：`priority` 枚举 + 资源分配表。
- **Kairo 实现方案**：`TaskItem.priority` 已有（low/normal/high/critical）；「已分配」展示 `assignee` 或未来 `resourceAssignments`。
- **优先级**：P0

### F-13-07 时限栏位（开始晚于 / 开始早于 / 结束晚于 / 结束早于）
- **手册依据**：第13章「项目大纲栏」→ 开始晚于、开始早于、结束晚于、结束早于
- **OmniPlan 行为**：对应任务安排检查器的四类时限约束：「开始不早于」「开始不晚于」「结束不早于」「结束不晚于」。
- **核心数据/逻辑**：四个可空约束日期：`startNoEarlierThan`、`startNoLaterThan`、`endNoEarlierThan`、`endNoLaterThan`。
- **Kairo 实现方案**：`TaskItem` 增加四个 `Date?` 约束字段；排程/手动改期时校验是否违背约束（违例检测的一部分）。
- **优先级**：P2

### F-13-08 成本栏位（任务成本 / 资源成本 / 总任务成本）
- **手册依据**：第13章「项目大纲栏」→ 任务成本、资源成本、总任务成本
- **OmniPlan 行为**：任务成本 = 与任务相关的非资源成本（可编辑）；资源成本 = 已分配资源的成本合计（只读，改资源分配才变）；总任务成本 = 两者之和。
- **核心数据/逻辑**：`taskCost`（直接成本）+ Σ(资源分配 × 资源费率 × 投入) 。
- **Kairo 实现方案**：`TaskItem.taskCost: Double?`；资源成本由 `ResourceAssignment` 聚合计算（依赖第16章资源模型）。
- **优先级**：P2

### F-13-09 基线差异栏位（计划的开始 / 开始差异 / 计划的结束 / 结束差异）
- **手册依据**：第13章「项目大纲栏」→ 计划的开始、开始差异、计划的结束、结束差异
- **OmniPlan 行为**：计划的开始/结束 = 基线日程中的计划时间；开始/结束差异 = 计划与实际时间之差。
- **核心数据/逻辑**：`baselineStart`/`baselineEnd`；差异 = 实际 − 计划。
- **Kairo 实现方案**：`TaskItem` 增加 `baselineStart/baselineEnd: Date?`（由 F-14-16 快照写入）；差异为计算列。
- **优先级**：P2

### F-13-10 宽延栏位（自由宽延 / 总宽延）
- **手册依据**：第13章「项目大纲栏」→ 自由宽延、总宽延
- **OmniPlan 行为**：自由宽延 = 单任务与其后续任务之间的空余时间；总宽延 = 任务可推迟而影响整个项目工期之前的空余时间。均只读。
- **核心数据/逻辑**：`freeSlack`、`totalSlack` 由排程图计算（依赖关键路径算法）。
- **Kairo 实现方案**：由 F-14-15 关键路径/拓扑排程器输出，作为计算列。Kairo 无排程引擎前不出。
- **优先级**：P3

### F-13-11 估算栏位（最小 / 预计 / 最大投入估算值，Pro）
- **手册依据**：第13章「项目大纲栏」→ 最小投入估算值、预计投入估算值、最大投入估算值
- **OmniPlan 行为**：任务投入的三点估算；默认预计值等于实际投入；最小/最大可由「模拟」按钮自动设置，是 Monte Carlo 模拟的输入。
- **核心数据/逻辑**：`estimateMin/estimateExpected/estimateMax: Double`。
- **Kairo 实现方案**：`TaskItem` 增加三个可选估算字段；配合 F-14-17 模拟用。
- **优先级**：P3

### F-13-12 挣值分析（Pro）— 成本组（ACWP / BCWP / CPI / CV / CV%）
- **手册依据**：第13章「挣值分析（Pro）」
- **OmniPlan 行为**：实际成本 ACWP = 已完成工作量 × 资源费率（真实花费）；挣值 BCWP = 已完成工作的计划预算；成本绩效指数 CPI = BCWP ÷ ACWP（>1 低于预算，<1 超支，=1 恰好）；成本差异 CV 及 CV% 表示相对挣值的货币差与百分比。前提是先设基线。
- **核心数据/逻辑**：基线 + 当前编辑日期 + 投入/完成的投入 + 资源费率。
- **Kairo 实现方案**：一组只读计算列，依赖基线快照（F-14-16）与资源费率（第16章）。Kairo 引入成本模型后作为进阶报表。
- **优先级**：P3

### F-13-13 挣值分析（Pro）— 进度组（BCWS / SPI / SV / SV%）
- **手册依据**：第13章「挣值分析（Pro）」
- **OmniPlan 行为**：计划值 BCWS = 按初始安排到目前应完成工作的预算成本；进度绩效指数 SPI = BCWP ÷ BCWS（越大越超前）；进度差异 SV 及 SV% = 计划值减挣值。
- **核心数据/逻辑**：基线 + 当前编辑日期 + 计划成本曲线。
- **Kairo 实现方案**：与成本组同构的计算列，输出「超前/落后」指标。
- **优先级**：P3

### F-13-14 挣值分析（Pro）— 完工预报组（EAC / BAC / VAC / TCPI）
- **手册依据**：第13章「挣值分析（Pro）」
- **OmniPlan 行为**：完工估算 EAC = 实际最终成本；完工时预算 BAC = 全部工作的初始预算；完工差异 VAC = BAC − EAC（负 = 超支）；待完成绩效指数 TCPI = 为不超预算当前需维持的 CPI，≠1 表示建议修正。
- **核心数据/逻辑**：基线预算 + 实际进度外推。
- **Kairo 实现方案**：计算列，输出预算健康度建议。属 Kairo 远期指标。
- **优先级**：P3

### F-13-15 过滤项目大纲
- **手册依据**：第13章「过滤项目大纲」「过滤器备注」
- **OmniPlan 行为**：视图 > 过滤任务（Option-Command-F）打开条件表单，可加条件、Option-点按 + 号建嵌套条件组；可保存/重置/恢复过滤器。过滤期间只显示符合条件任务且只可编辑可见任务；顶部过滤栏显示隐藏数并提供刷新/编辑/删除。默认新任务不受过滤器影响；过滤时打印/导出只含可见任务。
- **核心数据/逻辑**：过滤器对象（条件树，支持嵌套）+ 激活状态 + 可见集。
- **Kairo 实现方案**：Kairo 已有 `FilterClause` + `AIFilterTranslator.apply`；新增 `SavedFilter(name:clauses:)` 持久化与嵌套条件组（`FilterGroup`），`Project.filteredTasks` 已有骨架，补充「激活过滤器 + 过滤栏」UI。
- **优先级**：P0

## 第 14 章 甘特视图

### F-14-01 甘特视图结构（大纲 + 甘特图）
- **手册依据**：第14章「甘特视图」「甘特视图大纲」
- **OmniPlan 行为**：视图分左右两部分：左侧任务大纲（与项目大纲视图同构、栏可独立自定义），右侧甘特图（任务条 + 日期标头的可视化）。
- **核心数据/逻辑**：共享 `Project`；左侧复用大纲栏配置；右侧按日期绘制任务条。
- **Kairo 实现方案**（2026-10-18 重设计）：计划模式为三栏工作台——大纲列、时间画布、检查器。行骨架由**单一纵向滚动容器 + `LazyVStack`** 提供；时间画布为一个与内容等高、宽度为画布视口的 `Canvas` 叠加层，统一绘制网格、非工作带、今天线、任务条与跨行依赖线；文本标签按可见行覆盖。禁止两个独立滚动视图用滚动偏移同步。几何来自 `GanttLayout` v2 与 `KairoPresentation` 快照；视图不直接读取 `Project`。见 [02-architecture](../02-architecture.md#adr-013-呈现层与唯一写路径sprint-4)。
- **优先级**：P1

### F-14-02 层级编号
- **手册依据**：第14章「分组任务」
- **OmniPlan 行为**：层级编号模式：顶层为整数，子级逐层附加小数点（1 → 1.1 → 1.1.1）；平级编号模式：全部按整数平铺编号。
- **核心数据/逻辑**：大纲树 → 前序编号；模式切换（层级/平级）。
- **Kairo 实现方案**：基于 `parentID` 树（F-14-03）生成显示编号；`Project` 提供 `outlineNumber(of:)`。
- **优先级**：P1

### F-14-03 分组任务
- **手册依据**：第14章「分组任务」
- **OmniPlan 行为**：三种建组方式：结构 > 添加子任务（选中任务变组并带子任务）、结构 > 缩进（把选中任务缩进为上一任务子任务）、结构 > 群组（把所选任务包进新组）。任务获得第一个子任务时转换为群组。
- **核心数据/逻辑**：树结构（parent/children）+ 缩进/添加子任务/群组三类操作。
- **Kairo 实现方案**：`TaskItem` 增加 `parentID: UUID?`；`Project` 提供 `indent(task:to:)`、`addChild(to:)`、`group(tasks:)`（新建 `kind = .group` 的父任务并重挂子任务）。Kairo 现为扁平列表，此为其层级化第一步，P1。
- **优先级**：P1

### F-14-04 群组任务特性
- **手册依据**：第14章「群组任务的特性」
- **OmniPlan 行为**：群组自身特性少：名称自持；类型恒为群组（可含任务/里程碑/群组，空群组可作占位符）；投入 = 子任务投入之和；持续时间 = 首任务开始至末任务结束的跨度（非时长之和）；可有开始/结束时限影响子任务；可带相关性；给群组分配资源 = 分配给组内全部任务，群组本身不持资源。
- **核心数据/逻辑**：聚合规则：投入求和、持续时间取跨度、资源分配下推。
- **Kairo 实现方案**：`TaskItem.kind = .group`；`Project` 提供聚合计算（`groupedEffort`、`groupedSpan`）；资源分配做「组分配 → 下推子任务」的展开逻辑。
- **优先级**：P1

### F-14-05 相关性（类型 + 拖拽 + 代码输入）
- **手册依据**：第14章「使用相关性连接任务」
- **OmniPlan 行为**：相关性类型含 FS/SS/FF/SF；创建方式：大纲/甘特选中多任务点「连接」（默认 FS）、连接按钮下拉选类型、甘特图中从任务条首/尾箭头拖到另一任务首/尾（决定类型）、在「从属/必要条件」栏输入相关性代码（如「1SS」「4.1FS-1d」；裸 ID 默认 FS，可带前置/延隔）。创建后从属任务自动重排以遵从相关性；无法满足时产生违例。
- **核心数据/逻辑**：`TaskDependency(sourceID, type, lag)`；`lag` 前置/延隔时间；排程传播 + 违例检测。
- **Kairo 实现方案**：`dependencies: [UUID]` 升级为 `[TaskDependency]`（含 type/lag）。`Project` 增加环检测与违例检测（依赖未满足 → 违例）。甘特拖拽建线 P1，相关性代码文本输入 P2。
- **优先级**：P1

### F-14-06 重复任务
- **手册依据**：第14章「重复任务」
- **OmniPlan 行为**：任务可指定重复规则（日/周/月/年 + 间隔值 + 详情参数），按开始/结束时间展开实例；「停止重复」把重复任务改回常规任务并取消未来事件。重复任务在大纲与甘特中表现为收起的分组，内含每个实例。
- **核心数据/逻辑**：`recurrenceRule`（频率、间隔、详情、范围）+ 实例展开（RRULE 语义）；实例 = 子任务列表。
- **Kairo 实现方案**：`TaskItem` 增加 `recurrence: RecurrenceRule?`（模型可复用 `DateComponents` 或自建 RRULE 子集）；展开时按规则生成实例并作为子任务挂到组任务下。
- **优先级**：P2

### F-14-07 拆分任务
- **手册依据**：第14章「拆分任务」
- **OmniPlan 行为**：结构 > 拆分任务（Option-Command-S）弹出窗口调整两段长度与中断后继续时间；拖一段到另一段上可重新合并；分级时允许拆分的开关决定拆分是否保留。
- **核心数据/逻辑**：任务 → 多段连续工作区间（`[TaskInterval(start, end)]`）；中断区间不计持续时间。
- **Kairo 实现方案**：`TaskItem` 增加 `intervals: [TaskInterval]`（为空表示单段）；甘特条按区间分段绘制；合并 = 清空 `intervals`。
- **优先级**：P3

### F-14-08 吊床任务（Hammock）
- **手册依据**：第14章「创建吊床任务」
- **OmniPlan 行为**：吊床任务时长同时取决于其前置任务的完成时间与后继任务的开始时间；排程中时长自动伸缩以填满两侧约束。需小心设置方向性相关性避免循环。
- **核心数据/逻辑**：`kind = .hammock`；时长 = 后继最早开始 − 前置最晚完成（受两侧任务变化动态重算）。
- **Kairo 实现方案**：`TaskItem.kind` 增加 `.hammock`；排程器计算其动态时长。依赖排程引擎，P3。
- **优先级**：P3

### F-14-09 甘特图直接编辑
- **手册依据**：第14章「在甘特图中编辑」→ 绘制/删除相关性线、绘制任务的时限、手动安排任务、改变任务持续时间、调整任务完成情况
- **OmniPlan 行为**：从任务条首/尾拖箭头建相关性线、点选按 Delete 删线；Shift-拖拽任务首/尾创建设定时限（再 Shift-连按移除）；水平拖动任务条 = 手动安排（安排类型置为手动）；拖任务条右端牵引条改持续时间（Shift 取整）；拖任务条内房子形白点更新完成度。
- **核心数据/逻辑**：拖拽手势 → 写回 `startDate/dueDate/duration/progress/constraints/dependencies`；手动安排标记 `schedulingType = .manual`。
- **Kairo 实现方案**：Sprint 7 已实现画布拖拽（v0.4.0，设计稿 docs/archive/Sprint7-gantt-direct-edit/design.md）：拖条体 = 显式 startDate 锚定（等价手动安排语义）；拖右端 = durationDays（start 不变）；拖左端 = startDate + duration 同变（end 不变）；条端点外环带拖出建 FS 依赖线（方向决定前后驱，环检测复用 DependencyEditing）；点选依赖线 + Delete 删线。手势经 `CanvasDragSession` 状态机（100ms 节流 + finish 必提交末值）与 `GanttHitTesting` 纯函数命中测试；命令层复用 `updateTask(id:patch:)` / `addDependency` / `removeDependency`，零改动。里程碑仅拖改期；群组聚合条不可拖。时限绘制、进度白点拖拽留后续。

### F-14-10 更新任务完成情况
- **手册依据**：第14章「更新任务完成情况」
- **OmniPlan 行为**：同步更新按钮选择日期（默认今天）、是否允许部分完成、范围（全部/所选）；确认后完成百分比更新到该时刻；快捷键 Shift-Option-= 置 100%、Shift-Option-- 置 0%。
- **核心数据/逻辑**：按日期推进 `progress`；`completedAt`。
- **Kairo 实现方案**：见 F-12-06；另补两个置 0/100% 快捷键。
- **优先级**：P0

### F-14-11 重新安排未完成任务
- **手册依据**：第14章「重新安排未完成的任务」
- **OmniPlan 行为**：选择日期后，把「该日期前应完成而未完成」的任务移动到该日期起继续，整个日程更新，不影响其后任务。
- **核心数据/逻辑**：未完成任务集合 → 顺延起始时间 → 依赖链传播。
- **Kairo 实现方案**：`Project.reschedule(incompleteBefore:)`（见 F-12-07）。
- **优先级**：P2

### F-14-12 自定义任务标签与间隔跟踪
- **手册依据**：第14章「自定义任务标签」
- **OmniPlan 行为**：任务标签编辑器为任务/群组/里程碑三类各设「前缀 / 任务条 / 后缀」三个区域的栏位；间隔跟踪 = 把累计或间隔性的成本/投入显示在每行任务条下方或仅日期标头下方。
- **核心数据/逻辑**：标签区域配置（类型 × 区域 × 栏类型）+ 累计/间隔数据。
- **Kairo 实现方案**：甘特行标签数据驱动渲染；间隔跟踪作为累计 `effort`/成本的可选行。
- **优先级**：P2

### F-14-13 更改图表比例
- **手册依据**：第14章「更改图表的比例」
- **OmniPlan 行为**：右上角放大镜菜单或横向拖日期标头缩放可见日期范围；菜单含：自动（按项目跨度）、特定（分/时/日/周/月/季/年）、缩放以适合项目、缩放以适合所选对象、自定义标头（打开显示偏好）。
- **核心数据/逻辑**：时间轴缩放级别枚举 + 可见范围。
- **Kairo 实现方案**（2026-10-18 重设计）：缩放档位为日 / 周 / 月 / 适合项目，日宽分别为 32 / 12 / 5。启动取「适合项目」，无任务时取周。拖动表头平移时间窗；横向平移另见 F-14-18（触摸板/滚轮与画布拖拽），仍不做横向滚动条。见 [ui-redesign](../design/ui-redesign.md) §5.1。
- **自定义日宽**（2026-10-20 增补，Sprint 6 / T3）：在上述档位之外提供 2–120 点/天的连续自定义日宽，
  全轴由单一标量驱动（每天等宽、每周等宽）；刻度粒度按实际日宽推导（≥18 逐日 / ≥6 逐周 / 其余逐月），
  与三档预设及「适合项目」互斥（最后写入者胜）；偏好持久化到视图偏好 JSON 的 `customDayWidth` 键，
  不改 `.kairo` 项目文件格式。入口：工具栏标尺弹出面板（滑杆 / ± 步进 / 档位芯片 / 重置）、缩放菜单步进项、`⌘+` / `⌘-` / `⌘0`。
- **优先级**：P2

### F-14-14 非工作时数着色
- **手册依据**：第14章「设置非工作时数的颜色」
- **OmniPlan 行为**：视图 > 非工作时间选择「无/节假日/周末/全部」，以不同背景色突出不工作日期，帮助解释任务条跨度与实际工作日的差异。
- **核心数据/逻辑**：工作日历（正常时数 + 例外）→ 非工作区间 → 背景色。
- **Kairo 实现方案**：依赖第16章工作日历模型；甘特背景按日历画色块。月缩放时隐藏非工作带，避免条纹噪声；非工作带必须同时有表头标签与 VoiceOver 说明，不单独依赖颜色。
- **优先级**：P2

### F-14-15 重要路径（关键路径）
- **手册依据**：第14章「使用重要路径」
- **OmniPlan 行为**：默认按任务相关性 + 任务间宽延确定关键路径；吊床任务/固定开始项目产生的空闲时段长度、资源可用性也会影响（可在里程碑检查器配置）。可对整项目或单里程碑显示。
- **核心数据/逻辑**：关键路径算法（正推最早、逆推最晚、零宽延路径；可选并入资源约束）。
- **Kairo 实现方案**：`Project.criticalPath(to milestone:)` 纯计算（CPM：forward/backward pass + 总宽延=0）。Kairo 有依赖边即可实现，P2。
- **优先级**：P2

### F-14-16 基线衡量进度
- **手册依据**：第14章「通过基线衡量进度」
- **OmniPlan 行为**：设置基线按钮对当前日程做快照（默认名 = 今日日期）；之后变更只影响实际日程；支持任意数量基线；分割日程/双日程模式并排对比；基线/实际菜单切换对比对象。
- **核心数据/逻辑**：`Baseline(name, snapshotDate, tasks→baselineStart/baselineEnd)`；实际日程与基线对比差异。
- **Kairo 实现方案**：`Project.baselines: [Baseline]`；`Baseline` 存任务快照（或仅存时间/进度）；写回 `TaskItem.baselineStart/baselineEnd`。差异显示见 F-13-09。
- **优先级**：P2

### F-14-17 Monte Carlo 模拟（Pro）
- **手册依据**：第14章「使用模拟来预计里程碑的完成时间（Pro）」
- **OmniPlan 行为**：基于三点估算（最小/预计/最大投入）运行 Monte Carlo，输出里程碑按时完成的概率：每个日期旁水平条，1 条 ≈ 20% 概率（5 条 = 100%）。未设估算范围时结果无意义；提供自动估算功能。
- **核心数据/逻辑**：三点估算 → 随机采样（如三角分布）→ 模拟排程 → 完成日期分布 → 里程碑概率。
- **Kairo 实现方案**：`Project.monteCarlo(milestone:iterations:)` 纯计算（依赖估算字段 F-13-11 与排程器）；甘特里程碑旁画概率条。Kairo 远期，P3。
- **优先级**：P3

### F-14-18 甘特图横向平移（触摸板 / 滚轮 / 画布拖拽）
- **手册依据**：第14章「滚动甘特图」（含平移查看前后日期以检查相关性）
- **OmniPlan 行为**：触摸板双指横向滚动或拖动滚动条左右移动时间轴；缩放后仍可平移到任意日期区间。
- **核心数据/逻辑**：横向位移 → 时间窗起点（`windowStart`）位移；整天归一。
- **Kairo 实现方案**（2026-10-22，v0.6.0）：画布是「视口即时间窗」模型（无横向滚动容器），横向输入统一换算成 `windowStart` 位移。
  - **触摸板/滚轮**：`NSEvent` 本地监听捕获 `scrollWheel`，光标在画布内且横向分量占优（或 Shift+纵向）时消费；`HorizontalPanAccumulator` 累积亚日余量、跨整天才提交（布局把窗口起点归一整天），慢速滑动不丢位移也不「一天天蹦」。
  - **画布空白拖拽**：复用 F-14-09 的拖拽手势槽位，起点命中 `.none` 且该行无条时进入 `PanDragSession`；条/端点/依赖线上的拖拽仍归 F-14-09。
  - 方向内容跟手（右移看更早日期）；任何平移退出「适合项目」；Escape 取消本段拖拽（已提交的平移不回滚，同表头拖拽）。
  - 不做：横向滚动条、子日粒度窗口（会破坏 A7 黄金基线）。
- **优先级**：P1（v0.6.0 完成）

### F-14-19 大纲开始/结束日期列可编辑（日历弹层）
- **需求来源**：2026-10-22 用户提出（原话：左边开始和结束日期都需要可编辑，用日历组件快速选某一天）。
- **Kairo 实现方案**（v0.7.0）：大纲 `start` / `finish` 两列从只读文本改为可点击单元格，点击弹出月历弹层（复用 F-14-10 的 `CalendarPopover`，组件不改造）。
  - **开始列**：显示排期开始（保持与画布对齐），编辑写意图 `startDate`（`.setTaskStart`，可「清除」回落自动排期）；群组禁用。
  - **结束列**：显示排期排他端点，编辑写 `durationDays`（`.setTaskFinish`，start 传同一快照的排期起点）；最小可选日 = 起点次日（`ScheduleDateMath.minimumFinish`）；群组、里程碑、无排期禁用并给出原因。
  - 口径说明：开始列「显示排期结果、编辑最早开始意图」，与检查器同源；依赖可能使排期后移，单元格 tooltip 已说明。
  - 可测策略：`OutlineDateEditing`（KairoPresentation 纯函数）统一判定启用/原因/最小日，视图不自写规则；写回动作与撤销键（`task-start-*` / `task-finish-*`）与检查器完全同源。
  - 窄窗下列被降级隐藏（`outlineWidth < 376 / 454`），入口回落到检查器同名两行。
- **优先级**：P1（v0.7.0 完成）

## 第 16 章 资源视图

### F-16-01 资源创建与删除
- **手册依据**：第16章「资源列表」→ 创建和删除资源
- **OmniPlan 行为**：Return 新建、工具栏「添加」、拖入 macOS「联系人」卡片创建人员资源、情境菜单；Delete/「移去」删除。
- **核心数据/逻辑**：`Resource` 集合 CRUD + 联系人导入映射。
- **Kairo 实现方案**：新增 `Resource: Identifiable, Codable` 模型（name/email/type/unit/efficiency/usageCost/hourlyCost/workWeek/exceptions/contactID）；`Project.resources: [Resource]`；`ResourceView` 提供列表 CRUD。
- **优先级**：P1

### F-16-02 资源类型（人员 / 设备 / 素材）
- **手册依据**：第16章「资源类型」
- **OmniPlan 行为**：人员 = 以电子邮件地址唯一标识、跨项目保持身份；设备 = 工具机器硬件，无独特身份；素材 = 使用中消耗、以单位数计量。
- **核心数据/逻辑**：`ResourceType: person|equipment|material|group`；person 有 email 身份；material 按单位消耗。
- **Kairo 实现方案**：`ResourceType` 枚举；`email` 字段；素材分配带 `units`。
- **优先级**：P1

### F-16-03 资源群组
- **手册依据**：第16章「资源类型」→ 群组、分配群组、资源群组的特性
- **OmniPlan 行为**：资源群组 = 组合多个资源的容器（如团队）；把群组分配给任务 = 分级时从组内选成员执行，成员不可用则换人；把资源分配给组任务 = 下推到组内所有任务；群组的使用成本/小时成本/效率显示为成员平均值，输入新值应用到全体成员。
- **核心数据/逻辑**：`parentGroupID`（资源树）+ 群组聚合（平均值）+ 组分配 → 成员选择策略。
- **Kairo 实现方案**：`Resource.parentID: UUID?`；`ResourceView` 支持分组；分级时组分配展开为单成员。
- **优先级**：P2

### F-16-04 资源列表栏
- **手册依据**：第16章「资源列表栏」
- **OmniPlan 行为**：可自定义栏，栏位包括：附件、备注、唯一 ID、资源（名称）、单位（人员/设备=可用投入百分比；素材=总使用单位数）、效率（每人每投入量百分比，50% 效率花两小时做一小时）、使用成本（每次分配/每单位固定成本）、小时成本（每小时投入成本）、总成本（使用+小时成本）、总时数（投入小时和）、总使用次数、类型、自定义工作周（偏离默认周时出图标）、日程安排例外（有例外时出图标）。
- **核心数据/逻辑**：资源字段 + 聚合列（总成本/总时数/总使用次数）与图标指示列。
- **Kairo 实现方案**：`Resource` 模型字段直接映射；聚合列由任务分配表计算；「自定义工作周/日程安排例外」为日历模型（F-16-08/09）的指示图标。
- **优先级**：P1

### F-16-05 资源时间线与负荷图
- **手册依据**：第16章「资源时间线」
- **OmniPlan 行为**：时间线显示所选资源（未选 = 全部）的任务条，划分依据是资源分配；下方负荷图：蓝条 = 使用达可用单位 100%，粉红条 = 超负荷（可分级缓解）；未指定时间线显示未分配任务；支持与甘特相同的日期范围/标头缩放。
- **核心数据/逻辑**：按资源分组的任务条 + 负荷 = Σ分配单位/可用单位。
- **Kairo 实现方案**：`ResourceView` 时间线部分；负荷条颜色规则（≤100% 蓝 / >100% 粉红）直接实现。
- **优先级**：P2

### F-16-06 资源 - 任务分配拖放
- **手册依据**：第16章「资源视图」总述；「资源时间线」
- **OmniPlan 行为**：在资源与任务之间通过拖放互相分配；在时间线之间拖动任务可更改其分配。
- **核心数据/逻辑**：拖拽 → 写 `resourceAssignments`。
- **Kairo 实现方案**：`ResourceView`/时间线支持拖放，调用 `Project` 的分配写入。

### F-16-07 自定义时间线任务标签

- **OmniPlan 行为**：与甘特图类似，用所选栏数据跟踪间隔/累计信息，显示在资源时间线的任务标签上。
- **核心数据/逻辑**：时间线标签配置。
- **Kairo 实现方案**：复用 F-14-12 的标签配置机制。
- **优先级**：P3

### F-16-08 正常时数日历
- **手册依据**：第16章「安排正常时数」「为一个资源设置正常时数」
- **OmniPlan 行为**：正常时数 = 标准工作周设置（绿色块 = 工作时段，可拖边缘调一天时间范围、点选后方向键移动/Delete 删除、空白处拖/连按新建、Shift 拖绘红色不可工作块）；未选资源时编辑项目工作周，选中资源时编辑其个人工作周（偏离项目默认则「自定义工作周」栏出图标）；投入量换算依据项目检查器的周长度（如工作周 6 天 × 7 小时 → 周 42 小时）。

### F-16-09 自定义时数（例外日历）
- **手册依据**：第16章「安排自定义时数」
- **OmniPlan 行为**：自定义时数 = 特定日期的例外日历（节假日、半天、加班、休息日）；正常周以绿色虚线边框标示差异；迷你日历按月/年浏览；「自定义日」列表加号添加额外工作时数/非工作时数/完全休息日；资源可继承项目自定义日期（灰色条目，齿轮菜单显隐）；Pro 中订阅日历导入的时数用虚线块显示且不可直接编辑。
- **核心数据/逻辑**：`calendarExceptions: [ExceptionDate(date, kind, blocks)]`；项目级与资源级继承。
- **Kairo 实现方案**：`WorkCalendar.exceptions`；`ResourceView` 提供例外编辑面板；甘特/资源时间线按例外渲染背景。
- **优先级**：P2
