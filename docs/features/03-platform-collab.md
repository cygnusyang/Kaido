# 三、平台与协作功能拆解（OmniPlan 手册 ch.31–41）

> 来源：OmniPlan 4 macOS 版内置简体中文参考手册（`OmniPlan Help/zh-Hans.lproj`），章节 3100 仪表盘（Pro）/ 3200 导入导出 / 3300 报告与打印 / 3400 云工作 / 3500 多用户协作（Pro）/ 4000 偏好设置 / 4100 菜单命令与键盘快捷键。
> 本文件为 Kairo 的功能规格输入，只描述规格与落地建议，不写实现代码。
>
> 术语规约（与 04-glossary.md 一致）：相关性=任务间依赖；基线=计划快照；投入=工作时间；持续时间=实际经过时间；分级=自动重排以均衡资源；仪表盘→Kairo 定名「项目组合」；发布/订阅=跨项目资源负荷信息共享。
>
> 平台功能的 AI 时代口径：OmniPlan 的中心服务器协作、WebDAV 云同步、HTML 模板报告是「文件时代」的产物。Kairo 采用**本地优先 + 单文件持久化 + 文件级同步**，协作与报告交给 AI 层做语义化（合并建议、叙述性摘要），而非照搬服务器协议。

## F-31-01 新建项目组合（Portfolio）
- **手册依据**：第31章「新建仪表板」
- **OmniPlan 行为**：新建一个 .opld 仪表盘文件，可把多个项目文件拖入，形成并列对比多个项目摘要的独立窗口；仪表盘本身不是项目，不能直接编辑项目内容。
- **核心数据/逻辑**：`.opld` 独立文件格式；保存的是项目引用集合 + 视图配置，而非项目数据副本。
- **Kairo 实现方案**：Kairo 不做独立文件格式。项目组合 = 一个可保存的**组合配置**（`PortfolioConfig`：项目引用 UUID 列表 + 时间范围 + 显示项），存 UserDefaults/JSON。UI 上作为主窗口的一个「组合页」或独立窗口，而非另类文档类型。
- **优先级**：P2

## F-31-02 向组合添加项目
- **手册依据**：第31章「新建仪表板」
- **OmniPlan 行为**：通过表单浏览选择项目，或从 Finder 拖放；多个项目按行排列，每行含项目迷你甘特简图。
- **核心数据/逻辑**：项目文件路径/引用解析 + 去重。
- **Kairo 实现方案**：`PortfolioConfig.projectIDs` 增删；支持从文件选择器或拖放添加。Kairo 当前单窗口单项目，组合页允许多项目只读并列。
- **优先级**：P2

## F-31-03 项目概览行（迷你甘特 + 摘要统计）
- **手册依据**：第31章「在仪表盘中检查项目」→ 项目统计
- **OmniPlan 行为**：每行显示项目摘要（开始/结束日期、持续时间、与基线差异、完成%、成本），甘特简图用两色区分已完成/未完成；可切换「实际时间线」与「基线日程安排」两种显示基准。
- **核心数据/逻辑**：每个项目的摘要计算（复用 F-20-03 项目摘要）；基线可选。
- **Kairo 实现方案**：复用 `Project.summary` 只读计算属性，绘制简化甘特条（`progress` 着色）。基线比较依赖 F-14-16 基线快照，未做基线前只显示实际。
- **优先级**：P2

## F-31-04 空闲时间图表
- **手册依据**：第31章「在仪表盘中检查项目」→ 空闲时间图表
- **OmniPlan 行为**：组合中自动生成一行，表示各资源的忙/闲时段：白色=过去未使用，深灰=未来可用。用于判断资源何时可接新任务。
- **核心数据/逻辑**：按资源聚合跨项目的分配占用区间，与当前时刻比较。
- **Kairo 实现方案**：依赖资源分配模型（F-16-06 `resourceAssignments`）。AI 层可用同一份数据回答「谁下周三有空」「建议把新任务排给谁」。
- **优先级**：P3

## F-31-05 资源负荷概览（忙闲条图 + 投入饼图）
- **手册依据**：第31章「在仪表盘中检查项目」→ 显示资源
- **OmniPlan 行为**：窗口底部列出已分配邮箱的资源，每人显示忙/闲条图与「投入在哪些项目/空闲」的饼图；跨项目共享资源时能看出 100% 投入与超负荷。
- **核心数据/逻辑**：资源 × 项目 × 投入占比的分配矩阵。
- **Kairo 实现方案**：P3。先不做图表，改为 AI 摘要：「本周 3 人超负荷，建议将 X 任务移至 Y」。饼图/条图列为远期可视化。
- **优先级**：P3

## F-31-06 组合视图选项（概览模式 / 统计开关 / 时间范围）
- **手册依据**：第31章「在仪表盘中检查项目」→ 视图菜单
- **OmniPlan 行为**：项目概览可在甘特比较视图与条图视图间切换；可显隐统计数据与资源列表；时间范围预设（所有任务/今天至结束/本月/季度/今年/自定义）。
- **核心数据/逻辑**：视图模式枚举 + 时间范围过滤。
- **Kairo 实现方案**：`PortfolioConfig` 增加 `overviewMode`（`.gantt | .bars`）与 `timeRange`；SwiftUI 视图按配置渲染。
- **优先级**：P2

## F-31-07 实时联动
- **手册依据**：第31章「在仪表盘中检查项目」
- **OmniPlan 行为**：对共享到仪表盘的某项目做任何更改，仪表盘即时反映；点项目文档图标可打开该项目。
- **核心数据/逻辑**：项目文件引用 + 变更通知；仪表盘只读不编辑。
- **Kairo 实现方案**：组合页直接引用内存中的 `Project` 对象（或轻量快照 + 观察），`@Observable` 自动联动。Kairo 单窗口场景下天然满足。
- **优先级**：P2

## F-31-08 跨项目资源共享识别
- **手册依据**：第31章「在项目之间共享资源」；第35章「平衡项目间的资源负荷」
- **OmniPlan 行为**：当组合中的项目启用了资源负荷发布/订阅时，仪表盘能识别同一资源参与多个项目（可同时 100% 投入），暴露超负荷或空闲。
- **核心数据/逻辑**：跨项目的资源身份匹配（同一邮箱）+ 负荷发布/订阅状态。
- **Kairo 实现方案**：P3。Kairo 单库多项目时，资源以稳定 ID 跨项目匹配；AI 检查「同一人在两个项目都被 100% 分配」并给出重排建议。
- **优先级**：P3

## F-31-09 打印组合
- **手册依据**：第31章「打印仪表盘」
- **OmniPlan 行为**：所见即所得打印组合，宽度由窗口决定、不超过一页，超出部分垂直分页；可存 PDF。
- **核心数据/逻辑**：视图渲染 → 打印/PDF 输出。
- **Kairo 实现方案**：SwiftUI 视图直接走 macOS 打印面板即可，不单独设计。此项 P3，随组合页落地。
- **优先级**：P3

## F-32-01 导入任务（CSV/TSV）
- **手册依据**：第32章「从其他格式导入」
- **OmniPlan 行为**：打开对话框中勾选「允许导入识别的其他文件类型」，即可把 CSV/TSV 读入新文稿；CSV 格式以「导出 CSV 再查看」为样板（首行栏名，每行一个任务）。
- **核心数据/逻辑**：分隔符（逗号/制表符）+ 编码 + 栏名到任务字段的映射。
- **Kairo 实现方案**：提供「导入 CSV」入口，默认把标题/开始/结束/投入/进度/优先级等常见栏名自动映射。**AI 增强**：栏名不标准时（如「负责人」「工期」），由 AI 完成字段映射并让用户确认；这是 Kairo 与 OmniPlan 的最大差异点。
- **优先级**：P1

## F-32-02 导入 OmniOutliner（列映射 + 层级）
- **手册依据**：第32章「从其他格式导入」→ OmniOutliner
- **OmniPlan 行为**：从 .oo3/.ooutline 导入任务列表，弹对话框让用户选择「大纲栏 → 任务栏」的对应关系；多级大纲自动转为任务群组。
- **核心数据/逻辑**：大纲列结构 → 任务字段；缩进层级 → 父/子关系。
- **Kairo 实现方案**：Kairo 不引入 OmniOutliner 私有格式（P3）。同思路落地为「导入 Markdown 大纲 / 缩进文本清单」：按缩进建 `parentID` 树。AI 可把自由文本清单转成结构化任务。
- **优先级**：P3

## F-32-03 导入 Microsoft Project（.mpp/.xml，Pro）
- **手册依据**：第32章「Microsoft Project 支持（Pro）」→ 从 Microsoft Project 导入
- **OmniPlan 行为**：Pro 版可打开 MS Project 2003–2019 的 .xml/.mpp 文件；顶部出现蓝色通知栏报告导入问题；不活跃任务状态、部分自定义栏等会丢失或警告。
- **核心数据/逻辑**：.mpp（二进制）/.xml（开放格式）解析 + 数据保真损失清单。
- **Kairo 实现方案**：P3。若做，只支持 .xml 开放格式导入（子树：任务/资源/分配/相关性），`.mpp` 二进制解析成本高且依赖第三方库，不引入。导入后用「保真报告」列出丢失字段。
- **优先级**：P3

## F-32-04 导出 CSV（含编码选项）
- **手册依据**：第32章「导出为其他格式」→ CSV
- **OmniPlan 行为**：导出当前（可过滤后）任务列表为 CSV；提供多种编码选项解决非 ASCII 字符兼容。
- **核心数据/逻辑**：栏名集合 + 行数据序列化 + 编码选择。
- **Kairo 实现方案**：P1。导出当前过滤后的任务视图（含父级分层列），编码默认 UTF-8（可选 GB18030 便于中文办公软件）。
- **优先级**：P1

## F-32-05 导出 iCalendar（事件 / 待办双模式）
- **手册依据**：第32章「导出为其他格式」→ iCalendar
- **OmniPlan 行为**：导出 .ics，可选择「日历事件」或「任务列表待办」两种形态；事件模式可选「每个任务一个事件」或「每个工作时段一个事件」。
- **核心数据/逻辑**：任务日期 → iCalendar VEVENT / VTODO；日期范围切分。
- **Kairo 实现方案**：P2。复用日历同步（F-35-08）的同一套 .ics 生成器。Kairo 任务有起止日期与 `progress`，导出为 VTODO（含 percent-complete）最贴合。
- **优先级**：P2

## F-32-06 导出视图图像（PNG/PDF/TIFF/JPG）
- **手册依据**：第32章「导出为其他格式」→ 图片导出
- **OmniPlan 行为**：把甘特/资源/网络视图导出为静态图片，可选包含大纲、甘特图或资源时间线。
- **核心数据/逻辑**：视图渲染快照。
- **Kairo 实现方案**：SwiftUI `ImageRenderer` 即可把任意视图渲染为 PNG/PDF（macOS 14 原生）。作为分享/报告附件的基础能力，P2。
- **优先级**：P2

## F-32-07 导出网络图（Graphviz .gv）
- **手册依据**：第32章「导出为其他格式」→ Graphviz
- **OmniPlan 行为**：把网络视图导出为 Graphviz 文件，提供三种图表类型：工作分解结构（WBS 树）、节点式网络图（强调相关性路径）、箭头式网络图（相关性为线）。
- **核心数据/逻辑**：任务/群组树 + 相关性边 → DOT 语法。
- **Kairo 实现方案**：P3。若做，直接用任务树 + `TaskDependency` 生成 DOT 文本（零依赖）。此项更多服务于画图工具链，Kairo 内部用自有网络视图渲染即可。
- **优先级**：P3

## F-32-08 导出 Microsoft Project（.mpp/.xml，Pro）
- **手册依据**：第32章「Microsoft Project 支持（Pro）」→ 导出到 Microsoft Project
- **OmniPlan 行为**：导出 .mpp（首选）或 .xml，与 MS Project 2019 兼容；样式、效率、ALAP 等属性不随导出，完成百分比按 % Work Complete 映射。
- **核心数据/逻辑**：任务/资源/分配/相关性 → MSP 字段模型；保真损失规则表。
- **Kairo 实现方案**：P3。同导入思路，只考虑 .xml 导出；`.mpp` 不引入。
- **优先级**：P3

## F-32-09 导入导出数据保真策略
- **手册依据**：第32章「Microsoft Project 导入和导出中的杂项」
- **OmniPlan 行为**：明确列出跨格式时哪些字段会丢（样式、效率、ALAP、不活跃状态、自定义栏、不等分配、资源超负荷自动消解），导入时以违例栏/通知栏警告。
- **核心数据/逻辑**：字段保真矩阵 + 导入后差异报告。
- **Kairo 实现方案**：Kairo 的任何导入/导出都带一份**保真报告**（`ImportReport`：导入 N 任务、跳过 M 字段、K 个警告），这是 doc-style 要求的「差异透明」。AI 用一句话总结「这次导入丢了什么、怎么补」。
- **优先级**：P2

## F-33-01 多视图打印与组件选择
- **手册依据**：第33章「在 OmniPlan 中打印」
- **OmniPlan 行为**：标准 macOS 打印对话框内提供 OmniPlan 专属选项：按当前视图（甘特/资源/网络）打印；任务/资源视图可选择是否含大纲、甘特图、资源图表；群组展开/收合、备注显隐、缩放百分比。
- **核心数据/逻辑**：打印配置（视图 + 组件开关 + 缩放）→ 页面渲染。
- **Kairo 实现方案**：P2。SwiftUI 视图走系统打印面板，自定义 `PrintOptions`（含大纲列、备注）附加在打印 job 前渲染。AI 时代报告更多走 F-33-05 的叙述式输出，打印作为兜底。
- **优先级**：P2

## F-33-02 打印裁剪区域
- **手册依据**：第33章「在 OmniPlan 中打印」→ 裁剪
- **OmniPlan 行为**：拖拽裁剪框或输入开始/结束日期，只打印指定时间范围内的部分。
- **核心数据/逻辑**：日期范围 → 视图过滤。
- **Kairo 实现方案**：打印配置加 `dateRange` 过滤即可，随 F-33-01 实现。
- **优先级**：P2

## F-33-03 打印预设
- **手册依据**：第33章「在 OmniPlan 中打印」→ 打印设置存为偏好
- **OmniPlan 行为**：把当前打印配置存为预设，可应用到当前或所有打印机，可在偏好设置中管理。
- **核心数据/逻辑**：打印预设对象 + 预设列表。
- **Kairo 实现方案**：`PrintOptions` Codable 存 UserDefaults，提供预设选择。P2。
- **优先级**：P2

## F-33-04 自定义页眉页脚
- **手册依据**：第33章「自定义页眉和页脚」
- **OmniPlan 行为**：左/中/右三字段，可插占位符（页码、打印时间、最近修改时间、绝对路径、总页数、项目标题）；应用到主页/首页/奇偶页。
- **核心数据/逻辑**：页眉页脚模板字符串 + 占位符求值。
- **Kairo 实现方案**：P3。Kairo 打印用系统页眉即可，不自定义。若未来做，占位符求值是纯函数。
- **优先级**：P3

## F-33-05 叙述式 AI 报告（替代报告窗口）
- **手册依据**：第33章「使用报告窗口（Pro）」（项目概览 / 任务报告 / 资源报告）
- **OmniPlan 行为**：报告窗口按模板生成固定报告类型：项目概览（差异/完成/成本）、任务报告、资源报告；可打印或导出。
- **核心数据/逻辑**：项目数据 → 模板渲染 → 打印/PDF/HTML。
- **Kairo 实现方案**：**Kairo 用 AI 生成叙述式报告**，而非固定模板：输入结构化项目数据（`Project.summary` + 任务/资源/风险信号），输出 Markdown 周报（现状、进度、风险、下一步）。保留「导出 Markdown/JSON」作为机器可读层。固定模板报告降级为 P3 可选。
- **优先级**：P1

## F-33-06 HTML 完整报告导出（含 .ics 日历/待办附件）
- **手册依据**：第33章「使用报告窗口（Pro）」→ 导出 HTML 完整报告
- **OmniPlan 行为**：导出为一个文件夹：各报告类型的 HTML 页 + calendars 文件夹（里程碑与资源任务的 .ics 事件）+ todos 文件夹（各资源 .ics 待办清单）+ include 文件夹（图片与 CSS）。
- **核心数据/逻辑**：多页 HTML + 关联 .ics 附件 + 资源打包。
- **Kairo 实现方案**：P2。Kairo 若做完整报告导出，输出「Markdown 主报告 + 附件文件夹」更贴合 AI 时代（可直接进知识库/Obsidian/公众号流水线），.ics 附件复用之 F-32-05。
- **优先级**：P2

## F-33-07 自定义报告模板（HTML+CSS+标记）
- **手册依据**：第33章「自定义报告模板（Pro）」+「自定义模板标记」
- **OmniPlan 行为**：模板 = 含 HTML/CSS 的文件夹，用 `{@Token@}` 标记插入项目/任务/资源/挣值/Monte Carlo 数据，支持 `{@Tasks@}{@/Tasks@}` 等循环标记；自定义数据键自动生成标记。
- **核心数据/逻辑**：模板引擎（占位符 + 循环 + 数据键）；标记覆盖项目/任务/资源/路径/挣值/Monte Carlo 五类。
- **Kairo 实现方案**：P3。Kairo 不做 HTML 模板引擎。**替代**：把「模板」定义为「AI 提示词模板」（prompt 中的变量占位 + 数据注入），用户用自然语言描述报告结构，AI 填充。愿意写代码的用户可直接改 Markdown。
- **优先级**：P3

## F-33-08 挣值分析报告
- **手册依据**：第33章「可用的报告类型」→ 挣值分析；模板标记「挣值分析标记」
- **OmniPlan 行为**：报告/标记提供 EVM 指标：计划值 PV、挣值 EV、实际成本 AC、成本/进度差异与指数（CV/SV/CPI/SPI）、完工估算 EAC、完工预算 BAC、完工差异、完工绩效指数 TCPI 等。
- **核心数据/逻辑**：基线 + 实际进度/成本 → 挣值指标体系（详见 F-13-12..14）。
- **Kairo 实现方案**：P3。EVM 依赖基线、成本、工作时数完整模型，属远期。AI 层可在数据就绪后把指标翻成一句判断：「进度落后 12% 但成本可控」。
- **优先级**：P3

## F-33-09 Monte Carlo 模拟报告

## F-35-03 发布 / 刷新动作模型
- **手册依据**：第35章「设置同步和共享」「同步和共享配置选项」「与他人共享项目」

- **Kairo 实现方案**：**Kairo 用「集成」替代「动作」**：一个集成 = 目标（日历/导出/推送）+ 方向 + 触发时机（保存时/定时/AI 建议），模型上即 `Integration` 数组。声明式动作模型值得保留，但触发器更简单（保存即同步，无需 Bonjour 发现）。

## F-35-04 更改跟踪（接受/拒绝）

- **手册依据**：第41章「添加键盘快捷键」
- **OmniPlan 行为**：依赖 macOS 系统「应用程序快捷键」机制添加自定义快捷键。
- **核心数据/逻辑**：系统级快捷键覆盖。
- **Kairo 实现方案**：先依赖系统机制（零成本）；命令面板已覆盖「无快捷键命令」的发现路径。应用内快捷键自定义（P3）可选。
- **优先级**：P2

## F-41-06 自动化接口（Pro）
- **手册依据**：第41章「自动化菜单（Pro）」
- **OmniPlan 行为**：提供 AppleScript 库与 Omni 自动化（JavaScript）插件体系，可脚本化创建/编辑项目，有控制台与 API 参考。
- **核心数据/逻辑**：脚本 API 表面 + 插件加载。
- **Kairo 实现方案**：**Kairo 的「自动化」= AI 自然语言操作**（命令面板 + AI 助手直接调数据层 API），不提供用户脚本引擎。同时把核心模型导出为稳定 JSON Schema，供外部工具/AI 集成（与 F-32-09 同层）。
- **优先级**：P2
