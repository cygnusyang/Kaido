# Sprint 8 范围 —— 任务起止日期可自定义（检查器日历）

> 2026-10-21 · 状态：已与用户确认 · 发版目标：v0.5.0（feature 级）
> 用户原话：「在每个任务的"开始""结束"日期都需要可以自定义，设置的时候需要考虑交互，建议以日历组件的形式设置」
> 决策（用户 2026-10-21 确认）：
> 1. 「开始」写 `startDate`（用户意图锚点，与 0.4.0 拖条改写同一字段）；
> 2. 「结束」可编辑 = 计划结束（`scheduledFinish`），编辑时保持开始、改写 `durationDays`；`dueDate`（截止日期）保持独立字段与原义，不改；
> 3. 交互形态 = 点击字段弹出月历（Popover），行内显示 `YYYY-MM-DD`，支持清除与快捷项。

## 背景与现状

- 检查器任务页「排期」区（`Apps/macos/Sources/Workspace/Inspector/InspectorView.swift` §排期）当前：计划开始/计划结束**只读**、持续时间可编辑、截止日期可编辑（原生 `DatePicker` 无日历弹层交互设计）。
- 0.4.0 已让画布拖拽改写 `startDate`/`durationDays`（F-14-09），检查器缺对等的人工输入路径——用户无法精确指定日期。
- 语义基线（不得静默改动）：`startDate`=用户意图、不驱动自动排期；`dueDate`=截止、仅风险提示；`scheduledStart/scheduledFinish`=引擎计算；finish 为**排他端点**（1 天任务 start=11-02 → finish=11-03，条体覆盖 11-02 当天）。

## 本期范围（MECE）

1. **字段可编辑**：任务页「开始」「结束」均可自定义（任务/里程碑；群组仍聚合只读）。
2. **日历交互**：Popover 月历，含月份导航、今天高亮、选中态、非工作周末弱化、清除、「今天」「+1 周」快捷；键盘可达（Esc 关闭、方向键移动、Return 选定）；深浅色均按 `DesignTokens`。
3. **写回正确**：一次编辑 = 一步撤销；结束早于开始/零长度/里程碑/无排期/依赖冲突等边界有明确处置；不破坏既有 `dueDate`、约束、依赖语义。
4. **规格与测试**：`ui-redesign` 检查器规格同步；单测 + 离屏渲染验收；全量回归只增不减。

## 非目标

- 不做工作日历（US-E2-04）与非工作时长换算；不做时间粒度（时/分）编辑，仅日粒度。
- 不改 `.kairo` 格式版本（复用既有 `startDate` / `durationDays` / `dueDate` 字段，无新增字段）。
- 不做「结束」直接改 `dueDate` 的语义混用（截止日期仍是独立字段）。
- 不改画布拖拽行为与命中测试。
- 不做多选批量改期、不做大纲内联日期编辑。


## 补充裁定（2026-10-21 · 用户确认）

设计阶段查明既有缺陷：`ScheduleEngine` 从不消费每任务 `startDate`（只用作项目锚点推导），因此 v0.4.0 画布拖条改期实际不移动条体（登记 D-021）。用户裁定：**本版一并修引擎**（design.md §7 E1 方案 C）。

- 引擎：`kind != .group` 的显式 `startDate`（startOfDay 归一）作为开始下界，与项目锚点/时限/相关性下界取 max；后向传播不变。
- 观感变化：v0.4.0 曾写入但未生效的 `startDate` 在 v0.5.0 起生效，相关任务可能位移——发版说明与 CHANGELOG 必须如实登记（不写迁移工具）。
- E2 维持 finish 排他端点；E3 维持「开始可清除、结束不可清除」。
- 新增任务 S8-ENGINE（dev-coder-engine），文件范围 `Sources/KairoCore/**` + `Tests/KairoCoreTests/**` + `docs/02-architecture.md` §7。
