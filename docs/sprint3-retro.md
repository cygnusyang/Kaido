## 2. 做得好（保持）

1. **界面逻辑先落纯函数，再补离屏渲染测试**：甘特布局（16 项测试）与大纲层级编辑（10 项测试）在 `KairoCore` 内以纯函数实现，UI 只做投影与手势转发；`AppTests` 再用 `ImageRenderer` 离屏渲染，验证视图确实绘制，缩放、平移、命令面板与违例面板会改变画面。视觉美观与真人手感仍留给验收会。
2. **命令注册表单一事实源**：菜单栏与 ⌘K 面板消费同一份 `KairoCommandCatalog`，US-E4-05 验收 3「菜单与面板同源」由结构保证，而非两处手工同步。
3. **Demo 只写实际捕获输出**：MCP 会话为 2026-10-18 实际运行结果；发现原拟演示步骤不可达（模型只持有单侧时限，`constraint_window_too_narrow` 无法触发）时，改为可触发的 `constraint_is_prerequisite` 步骤，未改文案迁就。该步骤当时同样不可达（演示数据未锚定时间线，D-002），修复后由 GUI 测试复现。
4. **缺陷登记落地**：Sprint 2 行动项 A6 兑现，D-001 从发现到修复、登记、复验在同一提交内闭环，测试数由 159 覆盖不变（无回归）。
5. **自动化 hook 先设安全边界**：任务完成 hook 只在标题唯一命中时回写，0 个或多命中一律跳过并保持退出码 0，不阻塞 Claude Code；正负路径用真实 `.kairo` 文件逐一验证，并沉淀为 `TaskHookTests` 的自动化契约测试（含非法事件与并发锁）。
6. **GUI 测试发现真实缺陷**：离屏渲染与 Store 交互测试发现演示数据未设项目时间线，排期落在 1970 纪元（D-002）；修复后补 `SeedDataTests`，Demo §4 的违例步骤才可复现。测试不只固化现状，还修正了现状。
